## 1. 设计目标与约束

### 1.1 设计目标

1. **一套架构承载 P0–P4 全部演进，不推倒重来**（骨架可生长）
2. **契约稳定**：REST `/api/v1` + MQTT topic 一经冻结，模块可独立替换
3. **离线自足**：全部资源本地化，无外网依赖
4. **三层可拆**：开发期单机分进程模拟端-边-云，部署边界确认后仅改拓扑不改代码

### 1.2 设计约束

| 约束 | 来源 |
|---|---|
| 离线运行、无外网请求 | 决策 D1 |
| Windows 先行 → 国产化平板（麒麟/统信 + 飞腾/鲲鹏 ARM64） | 决策 D11 |
| 视频 H.265 源、端到端延迟 ≤0.5s | 确认 T2 |
| 语音离线、指令集有限 | 确认 T5 |
| C++ 高性能模块（视频/语音/推理） | 决策 D14 |
| 2D/3D 切换（单引擎双模式） | 决策 D13 |
| 非涉密安全基线 | 决策 D12 |

## 2. 总体架构设计

### 2.1 进程模型

```
┌─ Electron ────────────────────────────────────┐
│ main 进程：窗口/菜单/编排/Java 进程生命周期    │
│ renderer 进程：React UI + MapLibre + deck.gl  │
└──────────────┬────────────────────────────────┘
               │ HTTP（127.0.0.1:<随机端口>）
┌──────────────▼────────────────────────────────┐
│ Java sidecar（Spring Boot）                    │
│ 业务领域服务/流程状态机/持久化/静态托管/REST    │
└───────┬───────────────────┬───────────────────┘
        │                   │
 ┌──────▼───────┐   ┌───────▼────────────────────┐
 │ MQTT broker  │   │ C++ 服务（P1 桥接；P3 起）   │
 │ （NanoMQ）    │   │ 链路桥接/离线语音/视频网关    │
 └──────────────┘   └────────────────────────────┘
```

设计要点：① 所有进程仅回环（127.0.0.1）通信；② renderer 页面由 Java 托管（同源），天然无跨域问题；③ C++ 服务经 MQTT/REST 接入、可独立启停（对应自检模块清单）。

### 2.2 分层

| 层 | 组成 | 职责 |
|---|---|---|
| 表现层 | React + MapLibre + deck.gl | 界面、地图渲染、事件驱动 UI |
| 应用层 | Spring Boot 领域服务 + 规则引擎 | 业务、流程、持久化、决策 |
| 基础设施层 | MQTT、SQLite、静态资源（前端产物/瓦片） | 契约与数据底座 |
| 外部接口层 | UDP 组播桥接、视频网关、语音服务 | 设备侧接入 |

### 2.3 关键设计决策

| 决策 | 内容 | 理由 |
|---|---|---|
| 壳加载方式 | Electron 窗口加载 `http://127.0.0.1:<port>/`（前端由 Java 托管） | 单一托管点，壳层零静态资源，复用 P0 架构 |
| 端口协商 | `server.port=0` + 端口文件 + 健康轮询（500ms 间隔/30s 超时） | 避免端口冲突，壳与 Java 完全解耦 |
| 内部总线 | MQTT（前端 mqtt.js 走 MQTT over WebSocket） | 发布订阅、LWT 遗嘱消息做失联检测、云边端可扩展 |
| 桥接模式 | 链路侧 UDP 组播 → 桥接服务解析 → 发布 MQTT | 协议解析器可替换，协议文档缺失期用模拟解析器 |
| 决策抽象 | `DecisionEngine` 接口：态势 JSON → 方案 JSON | 规则引擎→本地模型→云边协同逐级替换算法不动契约 |
| 渲染分区 | canvas（WebGL）与 DOM（React）严格分离 | 地图帧率与界面响应互不拖累 |

## 3. 模块设计

### 3.1 壳层（shell，Electron main）

- **编排状态机**：启动 → 拉起 Java（`jre\bin\java -jar`）→ 读端口文件 → 轮询 `/api/v1/health` 就绪 → 建窗加载 URL；退出 → 优雅关闭 → 超时强杀
- **模块清单**（自检编排数据源，对应 APP-04）：地图引擎 / 通信链路 / AI 引擎 / 集群管理 / 数据服务，每项 = health 接口的一个子状态
- 菜单/工具栏、单实例锁、启动失败错误弹窗（Java 异常 / JRE 缺失）
- **预留**：多窗口（APP-07）；Launcher 抽象接口（壳可替换为 Tauri 的隔离层）

### 3.2 渲染层（frontend，React）

| 目录 | 职责 |
|---|---|
| api/ | REST 客户端 + TS 类型（MapConfig 等，与后端契约同源定义） |
| map/ | MapView 容器、MapLibre 初始化、2D/3D 切换 |
| layers/ | deck.gl 图层管理（LayerManager） |
| stores/ | Zustand：mapStore / missionStore / targetStore / resourceStore / linkStore / planStore / uiStore / voiceStore（P3） |
| app/ | 页面装配（全局布局、T0–T7 面板） |
| design/ | 深色设计 tokens + 通用卡片组件 |

- **事件驱动模式**：MQTT 订阅 → 事件归一化 → 写 store → UI 更新；AI 事件（ai/event）同时触发语音播报与界面高亮。

### 3.3 地图渲染模块

- 初始化：fetch `/api/v1/map/config` → 建 MapLibre 实例（raster style，本地瓦片 URL 模板）
- **2D/3D 切换**（MAP-02）：同一实例内 `pitch 0 + terrain 关` ↔ `pitch 倾斜 + terrain/fill-extrusion 开`，不重建引擎
- **deck.gl 图层注册表**（LayerManager）：轨迹层（订阅 telemetry/uav/*）、热点层、目标锁定框层（订阅 target/*）、热力层、Tile3D（预留）
- 性能原则：图层数据**增量更新**（增删改单元素，不全量重建）；React 仅负责 DOM 面板

### 3.4 后端业务模块（Java）

- 包结构：`com.mapapp.{controller, service, domain, repository, decision, mqtt, lifecycle, config}`
- 领域模块：scenario、mission、group、target、link、plan、report、assess、resource
- **流程状态机**（BIZ-01）：T0→T1→…→T7 前向流转 + 阶段内循环（重新检测/自动优化/调整方案）；转移规则集中在 `MissionStateMachine` 单点，三场景差异以配置注入
- **规则引擎**（AI-01..04）：`DecisionEngine` 接口 → `RuleDecisionEngine` 实现；下设 PlanGenerator / ThreatScorer / CoverageCalculator 子接口，演示级规则集中一处、可整体替换
- **生命周期**（lifecycle）：端口文件原子写入、优雅关闭钩子
- **静态托管**（config）：前端产物挂 `/`、瓦片挂 `/tiles/**`、报告下载挂 `/reports/**`

### 3.5 消息与桥接

- MQTT 接入：Java 侧 paho / spring-integration 客户端；前端 mqtt.js（broker 开启 ws 端口，仅本机监听）
- topic 常量类与契约（TRD 5.2）一一对应，禁止散落字符串
- **桥接服务**：`Parser` 接口（UDP payload → TelemetryEvent[]）；组播地址/端口可配置；P1 先用模拟解析器联调，协议文档到位后替换

### 3.6 视频模块（P3 预留）

- ZLMediaKit 旁路进程；Java 经其 HTTP API 做信令（拉流/启停转码/查询通道）；前端 WebRTC 播放组件
- 转码链：RTSP(H.265) → FFmpeg 转 H.264 → WebRTC 分发
- 通道状态经 topic `video/channel/{id}/status` 广播

### 3.7 语音模块（P3 预留）

- sherpa-onnx 封装：流式识别回调（音频流 → 文本），独立 C++ 服务进程，经 MQTT/REST 与主系统交互
- **意图匹配**：指令表（关键词/正则）+ 动作映射；未命中时播报"请再说一遍"
- **对话状态机**：空闲 → 系统播报（TTS）→ 聆听（VAD 断句）→ 识别（ASR）→ 动作执行 → 回复播报

### 3.8 AI 决策模块

- `DecisionEngine` 服务挂载在 Java（规则实现）；P3 起本地推理服务（llama.cpp/ONNX，独立进程）以**适配器模式**接入同一接口
- 对外统一暴露 REST `/api/v1`（plans/recommend、scenarios/recommend），算法替换不影响调用方

## 4. 关键流程设计

### 4.1 应用启动与自检（P0/P2）

main 启动 → 拉起 Java → 健康就绪 → 开窗 → 加载页面 → fetch map/config → 地图初始化 →（P2）自检界面聚合 `/api/v1/health` 各模块子项 → 用户确认 → 进入 T0

### 4.2 遥测数据流（P1）

UDP 组播 → 桥接解析 → MQTT `telemetry/*` → 前端订阅 → LayerManager 增量更新；失联检测：节点 LWT（retained `node/{id}/state`）+ 心跳超时 → 发布 `alert/warn`

### 4.3 任务流程流转（P2）

阶段进入 → 对应面板加载 → 用户/AI 动作 → 转移条件判定（MissionStateMachine）→ 写 `mission/{id}/phase` 事件 → 下一阶段；阶段内循环动作（自动优化/调整方案）不改变当前阶段

### 4.4 语音对话（P3）

`ai/event` 触发系统播报 → TTS → 播完进入聆听 → VAD 断句 → ASR → 意图匹配 → 动作执行（API 调用/界面联动）→ 生成回复 → TTS 播报

### 4.5 视频播放（P3）

用户选择通道 → Java 信令 ZLMediaKit 拉流 + 启转码 → 返回 WebRTC 播放参数 → 前端建立连接播放 → 状态广播

### 4.6 断链续行（P4 预留）

本地事件队列持久化 → 链路恢复 → 对账合并（幂等重放）→ 与云端一致性校核；端侧服务全部按"幂等 + 可重放"设计

## 5. 数据设计

### 5.1 存储分层

| 层 | 存储 | 内容 |
|---|---|---|
| 端 | SQLite（本地文件） | 任务/目标/资源/链路/方案/报告 + 事件队列 |
| 边/云 | PostGIS + 时序库 | 空间数据、遥测时序（P4） |
| 文件 | tiles/ 目录、reports/（PDF）、application.yml | 静态资源与配置 |

### 5.2 实体关系（文字版）

`Scenario 1─N Mission`；`Mission 1─N Group / Target / Plan / Report`；`Group 1─N UAV`；`Link N─N Node`；`Report 1─1 Mission`
（字段清单见 TRD 5.4；详细表结构与索引随 P2 详细设计定稿）

### 5.3 配置外置

`application.yml`：端口、绑定地址、地图中心/缩放、瓦片路径、组播地址；场景配置 JSON（P2 起，T0 场景选择 = 加载不同配置）

## 6. 接口设计要点

- **REST**：`/api/v1` 前缀；统一响应 `{code, message, data}`；前端降级（配置失败用内置默认值 + 非阻塞提示）
- **MQTT**：topic 与 QoS 严格按 TRD 5.2；retained 仅用于 `node/{id}/state`
- **进程间**：端口文件（`backend/run/app.port`，原子写）、健康探测 500ms/30s

## 7. 部署与打包设计

- 便携包布局：`mapapp.exe + resources/ + jre/ + backend/（jar+静态资源）+ tiles/（jar 外，见方案 10.3 倾向）+ reports/`
- 流水线：`pnpm build` → 产物复制 → `mvn package` → `jlink` 裁剪 JRE → `electron-builder --win portable` → zip
- 二期国产化：麒麟/统信 linux-arm64 **deb**；ARM 原生构建（ARM 机/ARM CI）；真机测试矩阵（两类 OS × 两类 CPU 代表机型）

---

## 8. 安全设计（非涉密基线）

- 网络面：全部服务仅绑定 127.0.0.1；MQTT ws 端口仅本机监听；不对外网卡开放
- 供应链：依赖锁定（pnpm-lock / Maven 清单）并归档备查
- 审计预留：关键操作日志表（P2 起，接口先行预留）
- 国密可选：SM2/SM3/SM4 组件预留接入点，默认不启用

---

## 9. 性能设计要点

- **渲染分区**：canvas 与 DOM 隔离；deck.gl 图层增量更新；瓦片走本地 HTTP + 浏览器缓存 + 视口周边预取
- **视频 0.5s 延迟预算分解**（示意，P3 实测校准）：

| 环节 | 预算 |
|---|---|
| 采集 + 编码（设备侧 H.265） | ~150ms |
| 局域网传输 | ~30ms |
| 网关转码 H.265→H.264 | ~100ms（硬件编码可压至更低） |
| WebRTC 分发 + 抖动缓冲 | ~100ms |
| 浏览器解码渲染 | ~50ms |
| **合计** | **~430ms ≤ 0.5s** |

## 11. 风险与技术债（设计层）

| 项 | 说明 | 应对 |
|---|---|---|
| deck.gl 与 MapLibre 视图同步 | 底图与叠层双引擎，坐标系/相机必须严格同步 | 采用 deck.gl 与 MapLibre 的官方 interleaved 绑定方式，P1 首日做最小验证 |
| H.265 硬解兼容性 | Chromium 不原生解码 H.265 | 转码 H.264 为主路径；WebCodecs HEVC 仅作实验备选 |
| 语音麦克风能力未知 | 降噪/阵列能力待真机 | 先跑通识别链路，真机再调降噪参数 |
| 端口文件竞态 | 异常退出残留旧端口文件 | 单实例锁 + 端口文件原子写 + 启动时校验端口存活 |
| 状态机扩展 | 三场景差异化组件与规则 | 转移表数据驱动，场景差异以配置注入，不在代码里分支 |
| 规则引擎被模型替换 | P3 起算法升级 | DecisionEngine 接口 + 适配器模式，契约不动 |
