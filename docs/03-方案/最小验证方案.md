- 版本：v0.3（待实施）
- 日期：2026-06-10
- 状态：路线与需求已确认 ✅
- 变更记录：v0.1 为浏览器 Web 形态；v0.2 变更为 **Windows 桌面应用形态**（Electron 壳 + Java sidecar）；v0.3 依据确认补充：项目非涉密、二期目标定为国产化平板（麒麟/统信 + 飞腾/鲲鹏 ARM64）、2D/3D 切换为已确认后续需求、C++ 用于高性能模块

## 1. 背景与目标

以 [gohypergiant/standard-toolkit](https://github.com/gohypergiant/standard-toolkit)（Hypergiant / Accelint 的前端标准库，Apache-2.0）为**模板**，借鉴其技术选型与架构思想，使用 **TypeScript + React 前端 + Java 后端** 构建地图应用。

**交付形态**：Windows 平台上的**独立桌面应用**（专门的 application 界面，非浏览器 Web 界面）；后期移植到 **国产化平板（麒麟/统信 + 飞腾/鲲鹏 ARM64）**（本期 Windows 跑通并保证架构兼容，不出 ARM 包）。

**MVP 目标（本次最小验证只做一件事）**：在离线环境下，验证桌面应用内「2D 地图漫游、拖拽、缩放」完整可用，并打通 React 前端 ↔ Java 后端 ↔ 桌面壳的完整链路。

验证三问：

1. **技术可行性**：MapLibre GL 在 Electron 渲染进程（Chromium/WebGL）中能否正常渲染离线瓦片？
2. **工程链路**：Electron 壳 ↔ Java sidecar ↔ 离线瓦片，全链路是否成立？
3. **桌面体验**：窗口 / 菜单 / 工具栏形态 + 拖拽缩放流畅度，是否符合"专门的应用界面"预期？

## 2. 决策记录（已确认）

| # | 决策项 | 结论 | 理由摘要 |
|---|---|---|---|
| D1 | 部署环境 | **内网/离线** | 不依赖任何公网瓦片服务，瓦片必须本地打包 |
| D2 | 使用区域 | **全球通用**（WGS84 / Web Mercator） | 无 GCJ-02 坐标偏移问题，OSM 数据生态完善 |
| D3 | 前端语言 | **TypeScript** | 与模板一致，接口契约有类型保障 |
| D4 | Java 职责 | **静态托管 + 配置接口** | 作为本地 sidecar，托管前端产物/瓦片并提供 `/api`，零瓦片代码 |
| D5 | 瓦片方案 | **预切栅格瓦片（XYZ 目录）+ 静态托管** | 无需额外组件；矢量瓦片留二期 |
| D6 | 验证区域 | **北京城区**（z3–z15，后续可追加其他城市） | 切片数千张、数十 MB，适合快速跑通 |
| D7 | 交付形态 | **Windows 桌面应用**（Electron 壳），非浏览器界面 | 专门的 application 窗口；后期需移植 ARM Ubuntu |
| D8 | Java 运行时 | **jlink 裁剪 JRE 随包分发**（约 40–60MB） | 目标机零预装依赖，适合离线内网 |
| D9 | 窗口形态 | **单窗口 + 菜单栏/工具栏** | 单窗口聚焦地图，菜单工具栏提供应用感与常用操作 |
| D10 | 分发格式 | **Windows 便携包 zip**（免安装解压即用） | 内网拷贝分发最省事；安装包留正式发布 |
| D11 | 终端平台 | **Windows 先行跑通；二期移植国产化平板（麒麟/统信 + 飞腾/鲲鹏 ARM64）** | 非 Android，Electron 路线成立；国产化平台出 linux-arm64 deb 包，构建与真机验证留二期 |
| D12 | 项目性质 | **非涉密** | 不涉及分保/保密要求，开源选型空间大，安全合规按常规基线执行 |
| D13 | 3D 需求 | **2D/3D 切换为已确认需求**（P1 实施，MVP 仅 2D） | 锁定 MapLibre 同引擎双模式（terrain + fill-extrusion）+ deck.gl；MVP 预留 dem/3dtiles 瓦片子目录 |
| D14 | C++ 角色 | **不强制；高性能模块优先采用 C++ 资产**（如视频流处理） | C++ 负责视频网关（FFmpeg/ZLMediaKit）、推理等性能敏感模块，与 Java 业务层以消息总线解耦 |

## 3. 模板借鉴说明

`standard-toolkit` 是**前端组件/工具库 monorepo**（无后端、无应用骨架），其地图包 `@accelint/map-toolkit` 技术栈为：MapLibre GL JS 5 + react-map-gl 8 + deck.gl 9 + turf。它不涉及桌面壳，故桌面层选型独立决策（D7）。

**借鉴（思想与选型）**：

- 技术选型对齐：MapLibre GL JS + react-map-gl（与模板同源同款组合）
- 分层思想：地图渲染层与业务层分离，地图实例封装为 hooks（参照其 `use-maplibre` / `create-map-store` 模式）
- 配置驱动：地图初始状态（中心点、缩放）由后端配置接口驱动（参照其 camera / viewport store 思想）
- 工程习惯：pnpm monorepo、Storybook 驱动 UI 开发（Storybook 建议二期引入）

**不借鉴（明确排除）**：

- 不直接依赖 `@accelint/*` npm 包（README 声明仅面向 Accelint 家族使用，且依赖面重）
- 不引入 deck.gl、军用网格（MGRS/GARS）、milSymbol 等与需求无关能力
- 不复制其业务组件代码，仅参考交互范式（如 [Map Toolkit Storybook](https://map-toolkit.accelint.io/) 的控件摆放）

## 4. 总体架构

```
Windows 目标机 · 便携包目录 mapapp\
├─ mapapp.exe              Electron 壳（窗口、菜单、生命周期）
├─ resources\              Electron 资源
├─ jre\                    jlink 裁剪 JRE（D8，零预装依赖）
└─ backend\                Spring Boot fat-jar + 前端产物 + 瓦片
```

**启动流程**：

1. 双击 `mapapp.exe` → Electron 主进程启动
2. 主进程执行 `jre\bin\java -jar backend\mapapp.jar`（`--server.port=0`）拉起 Java sidecar
3. 主进程读取 Java 写入的端口文件，轮询 `http://127.0.0.1:<port>/api/health` 至就绪（超时 30s 报错）
4. 创建应用窗口（含菜单栏/工具栏），加载 `http://127.0.0.1:<port>/`（**前端由 Java 托管**，复用 v0.1 架构，壳层零重复托管）
5. 退出：关窗 → 主进程级联终止 Java 子进程，不留孤儿进程

**运行期链路（全部本机回环，不对外网卡开放）**：

```
Electron 渲染进程（React + MapLibre GL）
      │ HTTP
      ▼
127.0.0.1:<随机端口>  Spring Boot 3
      ├─ /           前端页面（Vite 构建产物）
      ├─ /tiles/**   离线瓦片（静态托管）
      └─ /api/**     health、map/config
```

## 6. 需求范围与验收标准（MVP 核心）

### 6.1 地图能力（沿用 v0.1）

| 编号 | 能力 | 交互（桌面） | 交互（触屏，可选） | 验收标准 |
|---|---|---|---|---|
| F1 | 漫游 / 拖拽平移 | 鼠标左键按住拖动，地图跟随移动 | 单指拖动 | 连续拖拽 30 秒无卡顿、无白屏、无错位（瓦片异步加载，拖动中允许短暂灰块，释放后快速补齐） |
| F2 | 缩放 | 滚轮以**光标位置**为中心缩放 | 双指捏合缩放 | z3→z15 全程流畅，缩放中心不漂移 |
| F3 | 缩放控件 | 双击放大一级；地图内置 `+/-` 按钮；比例尺 | 双击放大 | 双击后级别 +1 且动画平滑；按钮点击各一次级别 ±1 |
| F4 | 范围约束 | minZoom=3、maxZoom=15；漫游不设边界（超出切片区域显示底色） | 同左 | 边界操作不报错、无 JS 异常；无瓦片区域显示底色而非崩溃 |
| F5 | 离线自足 | 所有资源来自本地 sidecar | 同左 | 断网（拔网线/飞行模式）下完整走查 F1–F4；DevTools Network 中**无任何外网请求** |
| F6 | 配置驱动初始化 | 页面加载时请求 `/api/map/config`，按其 center/zoom 恢复视角 | 同左 | 重启应用视角与配置一致；接口异常时前端降级为内置默认值并给出非阻塞提示 |

### 6.2 桌面应用形态（v0.2 新增）

| 编号 | 能力 | 内容 | 验收标准 |
|---|---|---|---|
| F7 | 独立应用窗口 | 双击 exe 启动独立窗口：自带标题栏与图标，任务栏独立条目，**无任何浏览器 UI 元素** | 窗口标题/图标正确；建议实现单实例（二次启动聚焦已有窗口，非必须） |
| F8 | 菜单栏 / 工具栏 | 菜单栏：文件（退出）、视图（回初始视角、全屏切换）、帮助（关于：弹出版本信息对话框）；工具栏：回初始视角、全屏、当前缩放级别/光标经纬度显示（放大缩小以地图内置 `+/-` 为准，工具栏不重复） | 各菜单项/按钮可用且行为正确；窗口全屏可切换；关于对话框显示版本号 |
| F9 | 进程生命周期 | 壳拉起 Java（读端口文件 + 轮询 `/api/health`）；Java 启动失败/JRE 缺失时**弹错误提示而非白屏**；关窗退出时级联终止 Java | 任务管理器验证：正常退出后无残留 `java.exe`；删除 `jre\` 目录后启动，出现明确错误提示 |

验收示例场景：双击启动 → 北京初始视角（center=[116.39, 39.90], zoom=11）→ 拖拽至故宫 → 滚轮缩至 z15 → 双击放大被 maxZoom 拦截 → 工具栏"回初始视角"复位 → 断网后重复以上操作全部正常 → 关闭窗口，任务管理器无残留进程。

## 8. 前后端接口契约

### 8.1 `GET /api/health`

```json
{ "status": "ok", "version": "0.2.0" }
```

### 8.2 `GET /api/map/config`

```json
{
  "center": [116.39, 39.90],
  "zoom": 11,
  "minZoom": 3,
  "maxZoom": 15,
  "basemap": {
    "type": "raster",
    "tiles": ["/tiles/{z}/{x}/{y}.png"],
    "tileSize": 256,
    "attribution": "© OpenStreetMap contributors"
  }
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| center | `[number, number]` | 初始中心点 `[lng, lat]`，WGS84 |
| zoom / minZoom / maxZoom | `number` | 初始缩放与范围约束，与瓦片实际层级一致（D6：3–15） |
| basemap.type | `"raster"` | MVP 固定为栅格 |
| basemap.tiles | `string[]` | 瓦片 URL 模板，MapLibre 的 `{z}/{x}/{y}` 占位符 |
| basemap.attribution | `string` | 版权标注，界面右下角展示（OSM 合规要求） |

**前端加载流程**：`启动 → fetch("/api/map/config") → 成功：初始化地图；失败：使用内置默认配置 + 界面提示（不阻塞页面）`。

### 8.3 端口与生命周期约定（sidecar 专属）

- Spring Boot 以 `--server.port=0` 启动（随机空闲端口），并将实际端口写入约定位置（如 `backend\run\app.port` 文件）
- 壳进程读取端口文件 → 轮询 `/api/health`（间隔 500ms，超时 30s）→ 就绪后开窗
- Spring Boot 仅绑定 `127.0.0.1`（`server.address=127.0.0.1`），端口不对局域网暴露
- 壳退出时向 Java 发送终止信号并等待退出；兜底超时强杀，保证无残留进程

## 9. 离线瓦片管线

### 9.1 切片范围与体积估算

- 北京城区 bbox：`116.05–116.75°E, 39.70–40.15°N`（约 60km × 50km）
- 层级 z3–z15，XYZ 目录结构 `tiles/{z}/{x}/{y}.png`
- 估算（供参考，以切图实测为准）：

| 层级 | 瓦片数（约） | 累计（约） | 体积（约） |
|---|---|---|---|
| z15 | ~2,600 | z3–z15 累计 ~3,500 张 | 数十 MB（城区 PNG 平均 10–25 KB/张） |
| z16（可选） | ~10,000 | +1 万张 | +150–250 MB，默认**不切** |

- 瓦片随便携包分发（打进 `backend\BOOT-INF` 静态目录或独立 `tiles\` 目录，二选一，见 10.3）。
- 若验收需要更细的街道视角再按需补切 z16。

### 9.2 生成方式

| 场景 | 方式 | 合规说明 |
|---|---|---|
| 开发验证（本次 MVP） | ① 脚本按 bbox 逐层抓取 `tile.openstreetmap.org`（限速、限并发）；② 或 QGIS：加载 OSM XYZ 图层 →「导出 → 生成 XYZ 瓦片（目录）」 | 必须遵守 [OSM Tile Usage Policy](https://operations.osmfoundation.org/policies/tiles/)：**禁止批量抓取、仅限开发验证、不得对外分发** |
| 生产（二期） | Geofabrik 区域 pbf + planetiler 自渲染（栅格或矢量），或采购允许离线分发的合规数据源 | 不依赖公共瓦片服务器 |

### 9.3 托管方式

瓦片目录放入后端工程静态资源（`static/tiles/` 或独立目录 + `WebMvcConfigurer` 资源映射），以 `/tiles/{z}/{x}/{y}.png` 提供；后续追加城市 = 向同一 XYZ 目录合并瓦片，**代码零改动**。

## 10. 工程结构与打包

### 10.1 源码结构

```
mapApp/
├─ docs/
│  └─ 最小验证方案.md          # 本文档
├─ frontend/                   # Vite + React + TS（渲染进程页面）
│  ├─ src/
│  │  ├─ api/                  # /api 客户端与类型（MapConfig 接口定义）
│  │  ├─ map/                  # 地图封装：MapView 组件、config hook、控件
│  │  ├─ layers/               # 预留：deck.gl 叠层（轨迹/热区/锁定框，P1）
│  │  ├─ stores/               # 预留：状态管理（Zustand，P1）
│  │  └─ app/                  # 页面装配（渲染层/业务层分离）
│  └─ vite.config.ts           # dev 时 proxy /api、/tiles → 本地 Java
├─ backend/                    # Spring Boot 3（sidecar）
│  └─ src/main/
│     ├─ java/…/mapapp/
│     │  ├─ controller/        # HealthController、MapConfigController
│     │  ├─ lifecycle/         # 端口文件写入、优雅关闭钩子
│     │  └─ config/            # 静态资源映射（前端产物 + 瓦片目录）
│     └─ resources/
│        ├─ application.yml    # 地图配置可外置（换城市只改配置）
│        └─ static/            # 前端构建产物；tiles/raster/（MVP）+ dem/、3dtiles/（预留，D13）
├─ shell/                      # Electron 主进程（TS/JS）
│  ├─ src/
│  │  ├─ main.ts               # 拉起 Java、等待健康、创建窗口、级联退出
│  │  ├─ menu.ts               # 菜单栏/工具栏定义与事件
│  │  ├─ preload.ts            # 预留（MVP 可空）
│  │  └─ java-launcher.ts      # jre 定位、子进程管理、端口文件读取
│  └─ package.json
├─ scripts/                    # 打包脚本：组装便携包目录 + jlink 生成 JRE
└─ README.md                   # 一键构建/启动说明
```

### 10.2 构建与打包流水线

1. `frontend`：`pnpm build` → 产物复制到 `backend/src/main/resources/static/`
2. `backend`：`mvn package` → fat-jar（含前端与瓦片）
3. `runtime`：`jlink` 生成裁剪 JRE（以 `jdeps` 分析结果为准选模块）
4. `shell`：`electron-builder --win portable` → 组装便携包目录：`mapapp.exe + resources + jre + backend`
5. 产出：`mapapp-0.2.0-win-portable.zip`，解压即用，目标机零预装（不依赖 JDK/Node/浏览器）

### 10.3 待定小项（实施时定，不影响方案）

- 瓦片放 fat-jar 内（单文件更整洁）还是 jar 外独立目录（更新瓦片不用重打 jar）：倾向后者，实施时确认。

## 13. 风险与备注

| 风险 | 应对 |
|---|---|
| 国产化平板移植（二期） | Electron 官方有 linux-arm64 二进制，麒麟/统信均为 Debian 系可出 deb；**从 Windows 交叉构建不可靠**，二期在 ARM 机或 ARM CI 构建；需真机专项验证 GPU 驱动/软件渲染性能与 Chromium 在国产化 OS 上的兼容性 |
| 便携包体积（Electron ~100–200MB） | 内网分发场景可接受；如体积变硬指标，可评估 Tauri v2（壳层可替换，Java sidecar 接入方式不变） |
| 杀毒软件误报（Electron 便携包偶发） | 验证期加入白名单；正式发布使用安装包 + 代码签名 |
| jlink 模块裁剪遗漏 | 构建后用 `jdeps` 校验 + 干净虚拟机冒烟测试兜底 |
| 端口冲突 / 防火墙拦截 | 随机端口（`server.port=0`）+ 仅监听 `127.0.0.1`，回环流量一般不触发防火墙 |
| WebGL 不可用 | Electron 自带 Chromium，WebGL 支持良好，风险远低于系统 WebView 方案；仍保留 Leaflet 降级预案 |
| 瓦片抓取合规与可用性 | 仅开发验证使用；生产走自渲染路线（第 9.2 节）；抓取限速并记录来源 |
| OSM 在中国境内的数据细节与注记风格 | 全球通用路线下接受；如需国内详图，二期接天地图（CGCS2000 ≈ WGS84，无偏移）或合规数据源 |
| 瓦片体积随城市/层级增长 | z3–z15 数十 MB 可控；z16+ 按需补切；多城市采用 XYZ 目录合并 |
