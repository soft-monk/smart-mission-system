## 1. 设计目标与约束

### 1.1 设计目标

1. **一套架构承载 P0–P4 全部演进，不推倒重来**（骨架可生长）
2. **契约稳定**：REST `/api/v1` + WebSocket 事件类型一经冻结，模块可独立替换
3. **流畅优先**：重资源（地图瓦片/视频）本地托管，局域网毫秒级加载
4. **网络可降级**：外网 API（LLM/ASR/TTS）异常时核心功能不受影响（规则兜底）
5. **逻辑前置**：业务状态与流程逻辑尽量在前端，后端做数据管道/托管/持久化
6. **服务端可分级**：开发期单机部署，P4 起可拆端-边-云，仅改部署拓扑

### 1.2 设计约束

| 约束 | 来源 |
|---|---|
| 终端可联网（非断网）；重资源本地化 | D1 |
| 服务端 C++（Drogon）：静态托管 + REST + UDP 接入 + WS 网关 | D4 |
| 地图预切北京瓦片本地托管，流畅优先 | D5 |
| 视频本地 mp4，前端 `<video>` 直接播放 | D6 |
| 语音/AI 在线 API（OpenAI 系），Python 桥接 | D7 |
| 实时通道 WebSocket 直推，无独立消息中间件 | D8 |
| 2D/3D 切换（单引擎双模式） | D12 |
| 业务逻辑前置到前端（Zustand） | D13 |
| 非涉密安全基线（内网暴露最小防护） | D11/D15 |
| 多终端并发共享态势 | D16 |
| 三场景共用 T0–T7 骨架，但同名阶段语义不同（见 TRD 1.2.1） | 界面需求初稿 6/8/9 章 |
| 三种视图形态（平板流程 / 全屏态势 / 二维建筑控制图）同源 | 界面需求初稿 7 章、TR-VIEW |
| 目标台账任务内唯一（跨界面强一致） | TR-TGT |

## 2. 总体架构设计

### 2.1 进程模型（B/S）

```
浏览器客户端（多台电脑/平板，可联网；开发期 Chromium 系，二期国产化平板浏览器）
   │  HTTP：页面 / 静态资源（瓦片/视频 mp4）/ REST 请求
   │  WebSocket：实时事件订阅（遥测 / 目标 / 阶段 / 告警）
   ▼
服务端主机（一台，Windows 先行；硬件规格 ⏸）
├─ C++ 后端（Drogon，单进程多线程）：
│   ├─ HttpController：REST API（/api/v1/*）+ /api/v1/ai/* 反向代理
│   ├─ WebSocketGateway：客户端连接管理、事件广播、心跳
│   ├─ UdpIngest：UDP 组播接收线程 → Parser 解析 → 发往 WS 广播队列
│   ├─ Repository：SQLite（sqlite3）持久化
│   ├─ StaticFiles：前端产物 / 瓦片 / 本地视频 / 报告 PDF
│   └─ Config：JSON 配置文件（监听地址/端口、组播地址、瓦片路径）
└─ Python AI 桥接（FastAPI，仅本机 127.0.0.1 监听，C++ 反代 /api/v1/ai/*）：
    ├─ POST /chat：LLM 对话与方案推荐（OpenAI 兼容 API）
    ├─ POST /stt ：音频 → 文本（Whisper API）
    └─ POST /tts ：文本 → 音频（TTS API）
    （API Key 从服务端环境变量读取，不进入前端）
```

设计要点：① 前端与 API 同源托管（无跨域）；② Python 桥仅本机可调、C++ 反代出口，密钥安全；③ 单一 WS 通道承担全部实时推送，客户端零中间件；④ C++ 进程即静态服务器，瓦片/视频/前端一体托管。

### 2.2 分层

| 层 | 组成 | 职责 |
|---|---|---|
| 表现层 | 浏览器内 React + MapLibre + deck.gl | 界面、地图渲染、业务状态与流程逻辑 |
| 应用层 | C++ Drogon（REST/WS/持久化/静态托管） | 数据管道、托管、持久化、推送 |
| AI 层 | Python FastAPI（在线 LLM/ASR/TTS 桥） | 外网 AI 能力统一接入 |
| 外部接口层 | UDP 组播接入、在线 API | 数据链与云服务 |

### 2.3 关键设计决策

| 决策 | 内容 | 理由 |
|---|---|---|
| 后端语言 | C++（Drogon） | 团队 C++ 主场；单进程承载 HTTP+WS+UDP，性能与集成度最优 |
| 实时通道 | 单一 WebSocket（服务端广播） | 去掉 MQTT 中间件；契约简单；断线重连自管 |
| AI 接入 | Python 桥 + C++ 反代 `/api/v1/ai/*` | 密钥不出服务端；供应商可替换；C++ 不直接依赖外网 API SDK |
| 业务逻辑 | 前置到前端（Zustand 状态机） | 界面功能迭代快；后端保持薄 |
| 视频 | 静态 mp4 + `<video>` | 零网关零转码；本地文件播放最简最流畅 |
| 渲染分区 | canvas（WebGL）与 DOM（React）严格分离 | 地图帧率与界面响应互不拖累 |
| 安全基线 | 内网监听 + 轻量访问控制（⏸）+ HTTPS 可选 | 非涉密下的最小防护；HTTPS 为语音采集前置 |
| **场景配置化** | T0–T7 为共用骨架，**同名阶段语义按场景不同**（TRD 1.2.1）；阶段标题/组件集/文案/业务对象由 `scenario` 配置注入，状态机与组件不硬编码场景差异 | 三场景共用流程但业务语义差异大（尤其场景三为建筑空间 + 人装协同）；新增场景不改状态机代码 |
| **目标单一台账** | 同一 Mission 内目标集合唯一，编号为任务内唯一键，所有界面（列表/详情/地图标记/方案/评估/报告）从同一 `targetStore` 渲染 | 界面图中同一目标跨页面类型与数量不一致，属缺陷；架构上以唯一台账根除 |
| **语音形态与状态机解耦** | 单一 `voiceStore` + `voice.state` 事件驱动；呈现形态（右下角悬浮球 / 页面内语音卡与对话行）由场景与页面配置决定 | 界面图中两种形态并存；交互逻辑与呈现解耦，避免两套实现 |
| **视图形态与数据同源** | 平板 T0–T7 流程界面、全屏态势图（第二屏/第三屏）、二维建筑控制图共用同一 mapStore/LayerManager，仅面板装配与相机预设不同 | 三种形态是同一态势的不同呈现，不应各建一套数据层 |

## 3. 模块设计

### 3.1 Web 客户端（frontend，浏览器渲染）

| 目录 | 职责 |
|---|---|
| api/ | REST 客户端 + TS 类型（MapConfig 等，与后端契约同源定义） |
| ws/ | WebSocket 客户端封装：连接/心跳/自动重连/事件分发 |
| map/ | MapView 容器、MapLibre 初始化、2D/3D 切换 |
| layers/ | deck.gl 图层管理（LayerManager） |
| stores/ | Zustand：mapStore / missionStore（含 T0–T7 状态机 + **scenarioKey 与场景配置**）/ targetStore（**单一目标台账**）/ resourceStore（含 TEAM/Person）/ linkStore / planStore / uiStore / voiceStore（P3） |
| app/ | 页面装配（全局布局、T0–T7 面板）；**面板按场景配置挂载**——三场景同名阶段的组件集不同（TRD 1.2.1） |
| views/ | 视图形态：`flow`（平板 T0–T7 主形态）/ `situation`（全屏态势图：隐藏导航与状态条）/ `control`（二维建筑控制图） |
| design/ | 深色设计 tokens + 通用卡片组件（含 AI 提示卡、状态指标条、时间轴控件、楼层切换条） |
| media/ | 视频面板组件（`<video>` 封装：进度/音量/全屏/通道切换）+ 多路图像流卡（缩放↔全屏） |

- **事件驱动模式**：WS 事件 → 事件归一化 → 写 store → UI 更新；AI 事件（ai.event）同时触发语音播报与界面高亮
- **断线重连**（WEB-06）：WS 心跳 + 指数退避重连 + 重连后拉取快照恢复状态；页面刷新从服务端恢复上下文

### 3.2 地图渲染模块

- 初始化：fetch `/api/v1/map/config` → 建 MapLibre 实例（raster style，服务端瓦片 URL 模板）
- **2D/3D 切换**（MAP-02）：同一实例内 `pitch 0 + terrain 关` ↔ `pitch 倾斜 + terrain/fill-extrusion 开`，不重建引擎
- **deck.gl 图层注册表**（LayerManager）：轨迹层（telemetry.uav.pos）、热点层、目标锁定框层（target.state）、热力层、Tile3D（预留）
- 性能原则：图层数据**增量更新**；React 仅负责 DOM 面板

### 3.3 C++ 服务端（backend，Drogon）

| 模块 | 职责 |
|---|---|
| HttpController | `/api/v1/*` REST 实现（health、map/config、scenarios、missions、groups、plans、targets、resources、links、assessments、reports、media/videos） |
| AiProxy | `/api/v1/ai/*` 反向代理到 Python 桥（127.0.0.1:<port>），超时与降级返回 |
| WebSocketGateway | 客户端连接表、事件广播（并发安全）、心跳（ping/pong 与超时踢除） |
| UdpIngest | 独立接收线程：组播 join → Parser 接口解析 → 事件入广播队列；心跳超时判定 → `node.state` 离线事件 |
| Parser（接口） | `UDP payload → 事件列表`；模拟解析器先行，协议到位后替换实现 |
| Repository | sqlite3 封装：任务/目标/资源/链路/方案/报告 CRUD；关键动作互斥（事务/版本号） |
| StaticFiles | 前端产物 `/`、瓦片 `/tiles/**`、视频 `/media/**`、报告 `/reports/**` |
| Config | JSON 配置加载（监听地址/端口、Python 桥地址、组播地址、地图中心/缩放） |

- 构建：CMake + vcpkg（drogon、sqlite3、nlohmann/json）；VS2022 编译
- 服务端启动即全部模块就绪；`/api/v1/health` 聚合各模块子状态供自检页面展示

### 3.4 Python AI 桥接（ai，FastAPI）

- 仅监听 `127.0.0.1`，由 C++ 反代出口；无状态，密钥从环境变量读取
- `/chat`：请求含提示词与上下文 → OpenAI 兼容 LLM API → 返回方案 JSON（带理由）；失败返回错误码由 C++ 转降级
- `/stt`：音频字节流 → Whisper API → 文本
- `/tts`：文本 → TTS API → 音频字节流
- 依赖：fastapi、uvicorn、openai sdk（或 httpx 直接调用兼容端点）

### 3.5 视频播放（P3）

- 服务端 `/media/**` 静态托管 mp4（H.264，浏览器原生解码）；`/api/v1/media/videos` 返回通道清单（名称 + URL）
- 前端 `<video>` 组件：进度/音量/全屏/倍速；通道切换 = 换 src；支持 HTTP Range 拖动
- 远程载荷流（RTSP 等）仅预留扩展点（VID-04），当前无需求

### 3.6 在线语音（P3）

- **采集**：浏览器 getUserMedia → WebSocket/HTTP 上送音频（需 secure context，见 8.2 HTTPS 前置）
- **识别**：C++ 转发 → Python `/stt` → Whisper API → 文本
- **对话**：意图规则匹配（指令集）→ 或 `/chat` LLM → 动作执行 + 回复文本
- **合成**：Python `/tts` → TTS API → 音频下发浏览器播放
- **对话状态机**：空闲 → 系统播报 → 聆听（VAD/按键）→ 识别 → 动作执行 → 回复播报

### 3.7 AI 决策（P3，规则兜底先行 P2）

- P2：规则兜底（前端或 C++ 内嵌演示级规则）：三方案生成、威胁评级、优先级排序
- P3：在线 LLM 推荐（`/api/v1/ai/chat` 代理）；LLM 失败时自动回落规则兜底
- 输出契约：方案 JSON（名称/方式/参与集群/成功率/效果/推荐理由），前端与规则、LLM 两路通用

## 4. 关键流程设计

### 4.1 服务启动与客户端接入（P0/P2）

启动 C++ 服务（静态托管/REST/WS 就绪）→ 客户端浏览器输入内网地址 → 页面加载 → fetch map/config → 地图初始化 →（P2）自检页面聚合 `/api/v1/health` 各模块子项 → 用户确认 → 进入 T0

### 4.2 遥测数据流（P1）

UDP 组播 → UdpIngest 接收 → Parser 解析 → WS 广播队列 → 全部在线客户端接收 → LayerManager 增量更新；失联检测：UDP 源心跳超时 → 广播 `node.state` 离线 → 界面告警

### 4.3 任务流程流转（P2）

前端 missionStore 状态机：阶段进入 → 对应面板加载 → 用户/AI 动作 → 转移条件判定 → 经 REST 落库 + WS 广播 `mission.phase` → 全部客户端同步进入下一阶段；关键确认动作服务端互斥。

**场景化要点**：状态机只持有 `phase`（T0–T7）与 `scenarioKey`，**不持有场景文案与组件清单**；面板装配时按 `scenarios/<key>.json` 的 `phases[]` 解析出该阶段标题与组件集（TRD 1.2.1）。`mission.phase` 事件负载带 `scenarioKey`，客户端据此选用本地场景配置渲染——三场景共用同一事件与同一状态机，差异全部落在配置层。

### 4.4 语音对话（P3）

`ai.event` 触发系统播报 → TTS API 合成 → 音频下发播放 → 播完进入聆听 → 浏览器采集 → 上送 → Whisper API 识别 → 意图匹配 → 动作执行（API 调用/界面联动）→ LLM 生成回复 → TTS 播报

**两种呈现形态**：对话状态机（idle → 播报 → 聆听 → 识别 → 动作 → 回复）与呈现解耦，状态经 `voice.state` 广播；呈现由场景配置的 `voiceMode` 选择 —— `ball`（右下角麦克风悬浮球，场景一）或 `inline`（页面内语音卡与对话行，场景二、三）。两形态共用同一 store 与同一状态机，不实现两套逻辑。

### 4.5 视频播放（P3）

前端获取通道清单 → `<video src="/media/xxx.mp4">` 直接播放（HTTP Range 拖动）→ 无任何服务端转码

### 4.6 断链续行（P4 预留）

服务端本地事件队列持久化 → 链路恢复 → 对账合并（幂等重放）→ 一致性校核；服务端按"幂等 + 可重放"设计

## 5. 数据设计

### 5.1 存储分层

| 层 | 存储 | 内容 |
|---|---|---|
| 服务端 | SQLite（本地文件，sqlite3） | 任务/目标/资源/链路/方案/报告 + 事件队列 |
| 边/云 | PostGIS + 时序库 | 空间数据、遥测时序（P4） |
| 文件 | tiles/ 目录、media/（mp4）、reports/（PDF）、config.json | 静态资源与配置 |

### 5.2 实体关系（文字版）

`Scenario 1─N Mission`；`Mission 1─N Group / Target / Plan / Assessment / MissionMetrics / Report`；`Group 1─N UAV`；`Mission 1─N Team`；`Team 1─N Person`；`Link N─N Node`；`Report 1─1 Mission`
（字段清单见 TRD 5.4；详细表结构与索引随 P2 详细设计定稿）

**两条数据约束（架构级）**：

1. **目标唯一性**：`Target` 以「Mission 内编号」为唯一键（`UNIQUE(mission_id, target_no)`）。所有界面（目标列表、目标详情、地图标记、方案参与目标、评估与报告）只读同一台账，禁止界面各自维护目标副本——这是对界面图中「同一目标跨页面类型/数量不一致」缺陷的架构级根除（TR-TGT-01）。
2. **方案双入口单台账**：`Plan` 同时服务 T1 编组方案与 T5 决策方案，以 `stage_side` 区分；两处界面的推荐/确认动作写同一实体，避免"编组确认的方案"与"决策选择的方案"不一致。

### 5.3 配置外置

`config.json`：监听地址/端口、Python 桥地址、组播地址/端口、地图中心/缩放、瓦片/媒体路径、**设计基准分辨率**（TR-UI-07）

`scenarios/*.json`（P2 起，**场景配置**，按 1.2.1 语义差异注入）：
- `key` / `name` / `alias`（三张任务方向卡文案与推荐角标）
- `phases[]`：各 T 阶段的**标题、组件集、业务对象**（如 T2 = 链路拓扑 | 云边拓扑 | 建筑空间感知）
- `voiceMode`：语音呈现形态（`ball` 右下角悬浮球 | `inline` 页面内语音卡/对话行）
- `statusBarSlots[]`：底部状态条可见槽位（全局框架元素出现范围不一致，用配置收敛而非硬编码）
- `metrics`：演示级指标规则参数（覆盖率、威胁打分权重等，可替换）

## 6. 接口设计要点

- **REST**：`/api/v1` 前缀；统一响应 `{code, message, data}`；前端降级（配置失败用内置默认值 + 提示）；监听内网网卡
- **WebSocket**：单通道 JSON 事件 `{type, data, ts}`，事件类型按 TRD 5.2 冻结；服务端广播 + 心跳保活
- **AI 代理**：`/api/v1/ai/*` 由 C++ 反代至 Python 桥（127.0.0.1），密钥不出服务端
- **静态**：`/`、`/tiles/**`、`/media/**`、`/reports/**` 由 C++ 静态托管，支持 Range 请求

## 7. 部署设计

- **服务端部署包**：`mapapp.exe（C++）+ static（前端产物/瓦片/视频）+ data（SQLite/报告）+ ai（Python venv + FastAPI 脚本）+ config.json + 启动脚本`
- 服务端进程管理：Windows 启动脚本（先起 Python 桥 → 再起 C++ 服务）；服务化/计划任务按需（P0 用脚本即可）
- **客户端**：零安装，浏览器访问 `http://<服务端内网IP>:<端口>/`；接入说明随部署包分发（WEB-07）
- 构建流水线：`pnpm build`（前端）→ `cmake + vcpkg`（C++）→ `pip install`（Python 桥）→ 组装部署包（release/）
- **二期**：服务端分级部署（边/云，P4）；国产化平板浏览器兼容验证（麒麟/统信，P4）；访问控制与 HTTPS 按需加固

## 8. 安全设计（非涉密基线）

### 8.1 网络面

- 服务端仅监听内网网卡；Python 桥仅监听 127.0.0.1（不对外）
- 轻量访问控制（访问口令 / IP 白名单，级别 ⏸ 待定）
- API Key 仅存服务端环境变量，前端不可见
- 依赖锁定（pnpm-lock / vcpkg baseline / pip requirements 锁定版本）

### 8.2 HTTPS（可选，语音前置）

- 默认 HTTP（内网）；P3 语音上线前需解决 secure context：**HTTPS 自签名证书 + 客户端信任导入**（推荐路径），或评估国产化浏览器策略
- 国密 SM2/SM3/SM4 组件预留接入点，默认不启用

## 9. 性能设计要点

- **流畅优先**：瓦片/视频本地托管（局域网毫秒级）；浏览器缓存 + 视口周边预取
- **渲染分区**：canvas 与 DOM 隔离；deck.gl 图层增量更新
- **多客户端并发**：服务端无状态 HTTP + WS 广播（一次发布、多端订阅）；事件批量合并（如 100ms 合并窗口）；静态资源走浏览器缓存
- **WS 规模预估**：20 终端 × 低频事件流，单机无压力；并发目标 ⏸ 待定后实测压载
- **多画幅适配**：界面图存在三种画幅（约 1536×1024 / 1672×941 / 1448×1086），基准分辨率待定（TR-UI-07）。设计上按基准等比缩放 + 安全边距，面板用弹性布局（flex/grid）而非绝对定位，避免多分辨率下错位
- **多视图共存开销**：三种视图形态共用同一 MapLibre 实例与图层管理器，切换视图只重挂载 DOM 面板、不重建地图实例；全屏态势视图隐藏流程面板以减少 DOM 节点

## 11. 风险与技术债（设计层）

| 项 | 说明 | 应对 |
|---|---|---|
| OpenAI 系 API 依赖（网络/费用/配额） | 海外网络与配额波动 | 规则兜底 + 降级播报 + 供应商可替换（代理层隔离） |
| 语音采集 secure context | 内网 HTTP 下 Chromium 系浏览器拒绝麦克风授权 | P3 前置：HTTPS 自签名 + 客户端信任导入；P2 末技术验证 |
| 国产化浏览器兼容 | 麒麟/统信浏览器内核与 WebGL 差异 | 开发期锁定 Chromium 系；二期真机矩阵；避免私有 API |
| 多客户端并发与算力 | WS 广播量随终端数增长 | 事件批量合并；广播队列设计；实测压载 |
| 服务端单点故障 | 主机宕机则全部不可用 | 备份策略；主备/冗余 ⏸ 按需 |
| 内网暴露面 | 服务监听内网网卡 | 最小网卡监听 + 访问控制 + API Key 服务端保管 |
| C++ 内存/并发安全 | 长连接与广播的并发正确性 | Drogon 成熟组件 + RAII + 互斥保护连接表；P0 起压测 |
| deck.gl 与 MapLibre 视图同步 | 双引擎坐标系/相机同步 | 官方 interleaved 绑定，P1 首日最小验证 |
| 状态机扩展（三场景） | 差异化组件与规则 | 转移表数据驱动，场景差异配置注入；阶段语义差异见 TRD 1.2.1，禁止把场景文案写进状态机 |
| **界面图框架不一致** | 语音入口形态不统一（仅场景一有右下角语音球）、底部状态条出现范围不一致 | 以「语音形态与状态机解耦」决策收敛为一套 voiceStore + 配置化呈现；状态条作为可开关的布局槽位，由场景/页面配置决定 |
| **多画幅并存** | 界面图三种分辨率（1536×1024 / 1672×941 / 1448×1086） | 基准分辨率待定（TR-UI-07）；弹性布局 + 等比缩放，不用绝对定位 |
| **场景三工作量显著偏高** | 建筑结构树、楼层切换、二维建筑控制图、人装协同路线均为场景三独有 | P2 只交付场景一闭环；场景三建筑相关能力单列评估（MAP-04/MAP-10/VIEW-01③），避免拖累 P2 门禁 |
| 链路协议文档缺失 | UDP 组播格式未知 | Parser 接口隔离，模拟解析器先行 |
| 瓦片数据合规 | OSM 政策约束 | 开发验证限政策内；生产自渲染或合规源 |
