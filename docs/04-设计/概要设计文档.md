## 1. 设计目标与约束

### 1.1 设计目标

1. **一套架构承载 P0–P4 全部演进，不推倒重来**（骨架可生长）
2. **契约稳定**：REST `/api/v1` + MQTT topic 一经冻结，模块可独立替换
3. **内网自足**：服务端与客户端均无外网依赖
4. **多端共享**：单一服务端数据源，多终端浏览器实时同步
5. **服务端可分级**：开发期单机部署，P4 起可拆端-边-云，仅改部署拓扑

### 1.2 设计约束

| 约束 | 来源 |
|---|---|
| 内网运行、无外网依赖 | D1 |
| 服务端 Windows 先行；客户端任意浏览器终端，二期国产化平板浏览器兼容 | D10 |
| 视频 H.265 源、端到端延迟 ≤0.5s | T2 |
| 语音离线、指令集有限（浏览器采集 + 服务端识别） | T5 |
| C++ 高性能模块（视频/推理/桥接），全部服务端部署 | D13 |
| 2D/3D 切换（单引擎双模式） | D12 |
| 非涉密安全基线（内网暴露最小防护） | D11/D15 |
| 多终端并发共享态势 | D16 |

## 2. 总体架构设计

### 2.1 进程模型（B/S）

```
浏览器客户端（多台电脑/平板；开发期 Chromium 系，二期国产化平板自带浏览器）
   │  HTTP(S)：页面 / 静态资源 / REST API（内网网址直达）
   │  MQTT over WebSocket：实时订阅（遥测 / 目标 / 链路 / AI 事件）
   ▼
服务端主机（一台，Windows 先行；硬件规格 ⏸）
├─ Java Spring Boot：前端托管 + REST API + 业务/流程/持久化/规则引擎
├─ MQTT broker（NanoMQ → EMQX）：内部总线 + 多客户端广播
├─ 静态资源：前端产物 + 瓦片（raster/dem/3dtiles 预留）+ 报告 PDF
├─ 数据：SQLite 起步 → PostGIS + 时序库（P4）
└─ C++ 模块（服务端部署）：
   ├─ UDP 组播桥接服务（数据链 → MQTT）
   ├─ ZLMediaKit 视频网关（H.265 → H.264 → WebRTC）
   ├─ 离线语音服务（sherpa-onnx ASR / piper TTS）
   └─ 本地 AI 推理（llama.cpp/ONNX，P3）
```

设计要点：① 前端与 API 同源托管（无跨域、无独立网关）；② 客户端零安装、零升级；③ 服务端模块可独立启停（对应自检模块清单）；④ 所有实时状态经 MQTT 广播，多终端天然一致。

### 2.2 分层

| 层 | 组成 | 职责 |
|---|---|---|
| 表现层 | 浏览器内 React + MapLibre + deck.gl | 界面、地图渲染、事件驱动 UI |
| 应用层 | 服务端 Spring Boot 领域服务 + 规则引擎 | 业务、流程、持久化、决策 |
| 基础设施层 | MQTT、SQLite、静态资源（前端产物/瓦片） | 契约与数据底座 |
| 外部接口层 | UDP 组播桥接、视频网关、语音服务 | 设备侧接入 |

### 2.3 关键设计决策

| 决策 | 内容 | 理由 |
|---|---|---|
| 部署形态 | B/S：服务端集中 + 浏览器客户端 | 多终端零安装、状态天然集中、升级只动服务端 |
| 服务端监听 | 绑定内网网卡 + 配置端口；回环仅供本机管理 | 局域网可达，同时控制暴露面（D16） |
| 内部总线 | MQTT（服务端 broker；前端 mqtt.js over WebSocket） | 发布订阅、LWT 失联检测、多端广播一致 |
| 桥接模式 | 链路侧 UDP 组播 → 桥接服务解析 → MQTT | 协议解析器可替换，协议缺失期用模拟解析器 |
| 决策抽象 | `DecisionEngine` 接口：态势 JSON → 方案 JSON | 规则→模型逐级替换算法不动契约 |
| 渲染分区 | canvas（WebGL）与 DOM（React）严格分离 | 地图帧率与界面响应互不拖累 |
| 安全基线 | 内网监听 + 轻量访问控制（⏸）+ HTTPS 可选 | 非涉密下的最小防护；HTTPS 为语音采集前置 |

## 3. 模块设计

### 3.1 Web 客户端（frontend，浏览器渲染）

| 目录 | 职责 |
|---|---|
| api/ | REST 客户端 + TS 类型（MapConfig 等，与后端契约同源定义） |
| map/ | MapView 容器、MapLibre 初始化、2D/3D 切换 |
| layers/ | deck.gl 图层管理（LayerManager） |
| stores/ | Zustand：mapStore / missionStore / targetStore / resourceStore / linkStore / planStore / uiStore / voiceStore（P3） |
| app/ | 页面装配（全局布局、T0–T7 面板） |
| design/ | 深色设计 tokens + 通用卡片组件 |

- **事件驱动模式**：MQTT 订阅 → 事件归一化 → 写 store → UI 更新；AI 事件（ai/event）同时触发语音播报与界面高亮
- **断线重连**（WEB-06）：mqtt.js 自动重连 + 重连后恢复订阅；页面刷新从服务端恢复上下文
- **浏览器兼容**（WEB-02）：开发期锁定 Chromium 系；避免浏览器私有 API；国产化浏览器差异靠真机矩阵验证

### 3.2 地图渲染模块

- 初始化：fetch `/api/v1/map/config` → 建 MapLibre 实例（raster style，服务端瓦片 URL 模板）
- **2D/3D 切换**（MAP-02）：同一实例内 `pitch 0 + terrain 关` ↔ `pitch 倾斜 + terrain/fill-extrusion 开`，不重建引擎
- **deck.gl 图层注册表**（LayerManager）：轨迹层（订阅 telemetry/uav/*）、热点层、目标锁定框层（订阅 target/*）、热力层、Tile3D（预留）
- 性能原则：图层数据**增量更新**；React 仅负责 DOM 面板

### 3.3 服务端业务模块（Java）

- 包结构：`com.mapapp.{controller, service, domain, repository, decision, mqtt, lifecycle, config}`
- 领域模块：scenario、mission、group、target、link、plan、report、assess、resource
- **流程状态机**（BIZ-01）：T0→T1→…→T7 前向流转 + 阶段内循环；转移规则集中在 `MissionStateMachine` 单点，三场景差异以配置注入
- **规则引擎**（AI-01..04）：`DecisionEngine` 接口 → `RuleDecisionEngine` 实现；PlanGenerator / ThreatScorer / CoverageCalculator 子接口，演示级规则集中一处、可整体替换
- **多端一致性**（BIZ-12）：关键确认类动作服务端互斥（后到者返回"正在执行/已执行"）；展示类操作无锁；状态变更统一经 MQTT 广播
- **健康聚合**（WEB-04）：`/api/v1/health` 返回各模块子状态，自检页面据此展示
- **静态托管**（config）：前端产物挂 `/`、瓦片挂 `/tiles/**`、报告下载挂 `/reports/**`
- **网络配置**（config）：监听地址/端口外置（application.yml）

### 3.4 消息与桥接

- MQTT 接入：Java 侧 paho / spring-integration 客户端；broker 开启 ws 端口（内网监听）；前端 mqtt.js 订阅
- topic 常量类与契约（TRD 5.2）一一对应，禁止散落字符串
- **桥接服务**：`Parser` 接口（UDP payload → TelemetryEvent[]）；组播地址/端口可配置；P1 先用模拟解析器联调，协议文档到位后替换

### 3.5 视频模块（P3 预留）

- ZLMediaKit 旁路进程（服务端）；Java 经其 HTTP API 做信令（拉流/启停转码/查询通道）；浏览器 WebRTC 播放组件
- 转码链：RTSP(H.265) → FFmpeg 转 H.264 → WebRTC 分发
- 通道状态经 topic `video/channel/{id}/status` 广播

### 3.6 语音模块（P3 预留）

- **采集**：浏览器 getUserMedia → WebSocket 音频流上送服务端（需 secure context，见 8.2 HTTPS 前置）
- **识别**：服务端 sherpa-onnx 流式 ASR；VAD 断句
- **合成**：服务端 piper TTS → 音频流下发浏览器播放
- **意图匹配**：指令表（关键词/正则）+ 动作映射；未命中时播报"请再说一遍"
- **对话状态机**：空闲 → 系统播报 → 聆听 → 识别 → 动作执行 → 回复播报

### 3.7 AI 决策模块

- `DecisionEngine` 服务挂载在 Java（规则实现）；P3 起本地推理服务（llama.cpp/ONNX，独立进程）以**适配器模式**接入同一接口
- 对外统一暴露 REST `/api/v1`（plans/recommend、scenarios/recommend），算法替换不影响调用方

## 4. 关键流程设计

### 4.1 服务启动与客户端接入（P0/P2）

服务端启动（java -jar）→ 客户端浏览器输入内网地址 → 页面加载 → fetch map/config → 地图初始化 →（P2）自检页面聚合 `/api/v1/health` 各模块子项 → 用户确认 → 进入 T0

### 4.2 遥测数据流（P1）

UDP 组播 → 桥接解析 → MQTT `telemetry/*` → 全部在线客户端订阅 → LayerManager 增量更新；失联检测：节点 LWT（retained `node/{id}/state`）+ 心跳超时 → 发布 `alert/warn`

### 4.3 任务流程流转（P2）

阶段进入 → 对应面板加载 → 用户/AI 动作 → 转移条件判定（MissionStateMachine）→ 写 `mission/{id}/phase` 事件 → 广播 → 全部客户端进入下一阶段；关键确认动作服务端互斥

### 4.4 语音对话（P3）

`ai/event` 触发系统播报 → 服务端 TTS → 音频下发播放 → 播完进入聆听 → 浏览器采集 → WebSocket 上送 → 服务端 VAD/ASR → 意图匹配 → 动作执行（API 调用/界面联动）→ 生成回复 → TTS 播报

### 4.5 视频播放（P3）

用户选择通道 → Java 信令 ZLMediaKit 拉流 + 启转码 → 返回 WebRTC 播放参数 → 浏览器建立连接播放 → 状态广播

### 4.6 断链续行（P4 预留）

服务端本地事件队列持久化 → 链路恢复 → 对账合并（幂等重放）→ 与云端一致性校核；服务端服务全部按"幂等 + 可重放"设计

## 6. 接口设计要点

- **REST**：`/api/v1` 前缀；统一响应 `{code, message, data}`；前端降级（配置失败用内置默认值 + 非阻塞提示）；监听内网网卡
- **MQTT**：topic 与 QoS 严格按 TRD 5.2；retained 仅用于 `node/{id}/state`
- **音频上行**（P3）：浏览器 → 服务端 WebSocket 音频流通道（与 MQTT ws 分开）
- **视频信令**（P3）：Java ↔ ZLMediaKit HTTP API

---

## 7. 部署设计

- **服务端部署包**：`backend jar + 前端产物 + 瓦片（jar 外独立目录）+ 报告目录 + 启动脚本`；JRE 由服务端环境提供（jlink 裁剪可选）
- 服务端进程管理：Windows 下可用启动脚本/计划任务/服务化（按需，P0 用脚本即可）
- **客户端**：零安装，浏览器访问 `http://<服务端内网IP>:<端口>/`；接入说明随部署包分发（WEB-07）
- 构建流水线：`pnpm build` → 产物复制 → `mvn package` → 组装服务端部署包（release/）
- **二期**：服务端分级部署（边/云，P4）；国产化平板浏览器兼容验证（麒麟/统信，P4）；访问控制与 HTTPS 按需加固

## 8. 安全设计（非涉密基线）

### 8.1 网络面

- 服务端仅监听内网网卡（回环仅供本机管理端口）；不对公网暴露
- 轻量访问控制（访问口令 / IP 白名单，级别 ⏸ 待定）
- 依赖锁定（pnpm-lock / Maven 清单）并归档备查

### 8.2 HTTPS（可选，语音前置）

- 默认 HTTP（内网）；P3 语音上线前需解决 secure context：**HTTPS 自签名证书 + 客户端信任导入**（推荐路径）或评估国产化浏览器策略
- 国密 SM2/SM3/SM4 组件预留接入点，默认不启用

---

## 9. 性能设计要点

- **渲染分区**：canvas 与 DOM 隔离；deck.gl 图层增量更新；瓦片走本地 HTTP + 浏览器缓存 + 视口周边预取
- **多客户端并发**：服务端无状态 HTTP + MQTT 广播（一次发布、多端订阅）；静态资源走浏览器缓存；视频并发转码受主机算力约束（VID-05 ⏸）
- **视频 0.5s 延迟预算分解**（示意，P3 实测校准）：

| 环节 | 预算 |
|---|---|
| 采集 + 编码（设备侧 H.265） | ~150ms |
| 局域网传输 | ~30ms |
| 网关转码 H.265→H.264 | ~100ms（硬件编码可压至更低） |
| WebRTC 分发 + 抖动缓冲 | ~100ms |
| 浏览器解码渲染 | ~50ms |
| **合计** | **~430ms ≤ 0.5s** |

## 11. 风险与技术债（设计层）

| 项 | 说明 | 应对 |
|---|---|---|
| **语音采集 secure context** | 内网 HTTP 下 Chromium 系浏览器拒绝麦克风授权 | P3 前置：HTTPS 自签名 + 客户端信任导入；P2 末技术验证 |
| **国产化浏览器兼容** | 麒麟/统信自带浏览器内核版本、WebGL/触屏表现差异 | 开发期锁定 Chromium 系；二期真机矩阵；避免浏览器私有 API |
| **多客户端并发与算力** | 视频并发转码、遥测广播量随终端数增长 | 并发目标待定；无状态 HTTP + 广播；网关可扩展；实测压载 |
| **服务端单点故障** | 主机宕机则全部终端不可用 | 备份策略（SQLite/报告定期备份）；主备/冗余 ⏸ 按需 |
| **内网暴露面** | 服务监听内网网卡，暴露于局域网 | 仅监听内网网卡；轻量访问控制；HTTPS 可选 |
| deck.gl 与 MapLibre 视图同步 | 底图与叠层双引擎，坐标系/相机必须严格同步 | 官方 interleaved 绑定方式，P1 首日最小验证 |
| H.265 硬解兼容性 | Chromium 不原生解码 H.265 | 转码 H.264 为主路径；WebCodecs HEVC 仅作实验备选 |
| 语音麦克风能力未知 | 降噪/阵列能力待真机 | 先跑通识别链路，真机再调降噪参数 |
| 状态机扩展 | 三场景差异化组件与规则 | 转移表数据驱动，场景差异以配置注入 |
| 规则引擎被模型替换 | P3 起算法升级 | DecisionEngine 接口 + 适配器模式，契约不动 |
