## 1. 系统概述

### 1.1 产品定位

智能任务管理系统：面向任务指挥与无人集群协同的**平板端**系统，集态势感知、AI 任务分析、集群编组、通信链路自组网、多源侦察融合、目标识别、任务决策、协同处置、效果评估于一体。三大任务模式（敏捷拒止布控 / 集群协同突击攻击 / 立体融合攻坚）共用 T0–T7 八阶段流程框架（T0 任务加载与场景选择 → T1 资源分组与任务编组 → T2 通信链路/云边协同/建筑空间感知 → T3 多源侦察展开与态势构建 → T4 目标识别评估与优先级筛选 → T5 任务决策与打击/处置准备 → T6 协同执行与引导 → T7 毁伤/效果评估与任务结束）。

系统强调：AI 语音交互（三段式：系统提示—用户语音—AI 回复）、人在回路决策（AI 推荐、用户确认）、多域协同（光电/雷达/电子/通信四类集群与战术小组、后方火力/云端算力）、前沿局部自治（断链续行）。

### 1.2 技术形态总览

- **交付形态**：桌面应用（Electron 壳 + React/TypeScript 渲染层），Windows 先行跑通，二期移植国产化平板（麒麟/统信 + 飞腾/鲲鹏 ARM64）
- **后端**：Java（Spring Boot）业务服务，本地 sidecar 起步，向端-边-云分布式演进（边界暂缓）
- **C++ 性能模块**：视频网关（ZLMediaKit/FFmpeg）、离线语音推理（sherpa-onnx）、信号处理（后续）
- **内部消息总线**：MQTT（已确认引入）
- **数据**：离线地理数据（栅格瓦片/DEM）+ SQLite 起步 → PostGIS/时序库
- **运行环境**：全离线自足；非涉密，常规安全基线

## 2. 技术决策基线（已确认，固化）

| 编号 | 决策项 | 结论 |
|---|---|---|
| D1 | 部署环境 | 内网/离线，不依赖任何公网服务 |
| D2 | 使用区域 | 全球通用（WGS84 / Web Mercator），无 GCJ-02 偏移 |
| D3 | 前端语言 | TypeScript |
| D4 | Java 职责 | 本地 sidecar：业务服务 + 静态托管（前端/瓦片）+ REST API |
| D5 | 瓦片方案 | 预切栅格瓦片（XYZ 目录）静态托管；矢量瓦片留 P2+ |
| D7 | 交付形态 | Windows 桌面应用（Electron 壳），非浏览器界面 |
| D8 | Java 运行时 | jlink 裁剪 JRE 随包分发 |
| D10 | 分发格式 | Windows 便携包 zip（正式发布再评估安装包） |
| D11 | 终端平台 | Windows 先行；二期国产化平板（麒麟/统信 + 飞腾/鲲鹏 ARM64，deb 包） |
| D12 | 项目性质 | 非涉密，安全按常规基线 |
| D13 | 3D 需求 | 2D/3D 切换为明确需求；MapLibre 单引擎双模式 + deck.gl；DEM 十几米级 |
| D14 | C++ 角色 | 不强制；高性能模块（视频/推理）优先采用 C++ 资产 |

| T2 | 视频参数 | 源编码 H.265、端到端延迟 ≤0.5s（网关转 H.264 + WebRTC）；路数/分辨率暂缓 |
| T3 | 无人机链路 | 数据链 + UDP 组播（外部链路协议文档待补充） |
| T4 | 消息总线 | MQTT 作内部消息总线（已确认引入，与链路协议无关） |
| T5 | 语音 | 指令集有限、必须离线（不依赖在线服务）；麦克风能力待真机 |
| T6 | AI | 推荐规则可固化（规则引擎起步）；本地模型先跑 Windows 10 开发机；平板算力未知 |
| T7 | 数据口径 | 演示级简单规则（威胁高/中/低按目标类型+距离打分、覆盖率=搜索网格占比、链路指标 1 秒刷新），全部可后续替换 |
| T8 | 角色权限 | MVP/P1 单角色全功能（无登录），权限体系后期再上 |
| T9 | 报告导出 | PDF + 本地目录（Electron 打印能力生成），界面保留历史任务列表 |
| T10 | 暂缓项 | 视频路数/分辨率、云边端部署边界、国产化平板具体型号——均不阻塞开发 |

## 3. 总体架构

### 3.1 逻辑架构

```
┌────────────────────────── 端（平板 / PC，Windows 先行）──────────────────────────┐
│  Electron 壳：窗口/菜单/生命周期/模块编排/单实例/打包分发                          │
│  ┌─ React + TypeScript 渲染层 ────────────────────────────────────────────────┐ │
│  │  设计系统（深色 tokens/组件库） · 业务面板（T0–T7） · 语音交互面板 · 报告   │ │
│  │  MapLibre GL（2D 底图 / 2D·3D 切换 / terrain / fill-extrusion）           │ │
│  │  deck.gl（轨迹动画/热点/热力图/锁定框/Tile3D 预留） · WebRTC 播放器        │ │
│  │  mqtt.js（内部总线订阅，MQTT over WebSocket）                              │ │
│  └────────────────────────────────────────────────────────────────────────────┘ │
│  本地服务层（Java Spring Boot sidecar）：业务/流程/持久化/静态托管/REST          │
│  支撑服务：MQTT broker（NanoMQ，随端部署） · SQLite · 报告 PDF                   │
│  C++ 模块：链路桥接服务（UDP 组播→MQTT）· 离线语音（ASR/TTS）· 视频网关（ZLMediaKit）│
└──────────────────────────────────────────────────────────────────────────────────┘
        ↕（P4：云边协同；部署边界暂缓，开发期单机分进程模拟）
┌─ 边缘节点（前沿指控单元）：区域服务 / 边缘推理 / 数据汇聚 ──────────────────────┐
└─ 云端（后方算力中心）：全局一致性校核 / 大模型 / 历史库 ───────────────────────┘
```

## 7. 分阶段实现与验证

### 7.1 阶段划分总览（共 5 个阶段）

| 阶段 | 名称 | 核心目标 | 前置 | 粗略周期（2–3 人规模） |
|---|---|---|---|---|
| P0 | 技术基线 | 桌面壳 + 2D 底图 + Java sidecar + 离线瓦片 + 打包链路（已在《最小验证方案》定义） | — | 0.5–1 周 |
| P1 | 态势底座 | 地图从"能看"到"能演"：动态图层、2D/3D、消息总线、深色界面骨架 | P0 验收通过 | 2–4 周 |
| P2 | 任务域 | T0–T7 全流程闭环（场景一，模拟数据）+ 规则引擎 | P1 验收通过 | 4–8 周 |
| P3 | 智能域 | 三轨：离线语音、H.265 视频 ≤0.5s、本地推理 | P2 验收通过 | 6–10 周（三轨可并行） |
| P4 | 协同域 | 云边端协同、断链续行、国产化平板落地 | P3 验收通过 | 4–8 周（含真机验证） |

> 总体量级约 **4–6 个月**（2–3 人、无并行外包）。周期为粗略估算，随人力与硬件信息到位调整；每阶段末设**阶段门（Gate）**，未过门不得进入下一阶段。

### 7.2 阶段门规则（通用）

每阶段结束时执行四步，全部通过后书面确认方可进入下一阶段；未通过项进入问题清单限期修复，不流入下一阶段：

1. **功能验收**：按本节所列需求条目（TR 编号）逐条核对
2. **非功能实测**：指标项实测（帧率/延迟/离线自足等）
3. **累计回归**：上一阶段验收项重跑，防倒退
4. **演示评审**：按演示场景走查，记录问题清单

阶段内需求变更按"确认 → 回写本文档 → 同步最小验证方案（若涉及其基线）"流程执行。

### 7.3 P0 技术基线（→ P1 门禁）

- 范围与验收：完全沿用《最小验证方案》v0.3（F1–F9 验收清单、断网自足、便携包分发、干净机验证）
- 附加门禁（为后续阶段铺路，随 P0 一并交付）：`/api/v1` 版本前缀落地；topic 命名规范冻结（5.2 节）；瓦片目录预留 `dem/`、`3dtiles/`；前端目录预留 `layers/`、`stores/`；依赖锁定清单
- **进入 P1 条件**：P0 验收清单全部通过 + 上述附加门禁就位

## 9. 风险与应对

| 风险 | 应对 |
|---|---|
| 国产化平板兼容性（GPU 驱动/软渲染/Chromium 表现） | 二期真机专项验证；ARM 原生构建（ARM 机/ARM CI）；壳层可替换预留 |
| 视频 H.265→H.264 转码延迟与算力（≤0.5s 硬指标） | ZLMediaKit + FFmpeg 硬件编码；ultrafast 预设兜底；P3 实测校准 |
| 离线语音与麦克风能力未知 | sherpa-onnx 原型先行；指令集有限降低识别难度；麦克风真机验证后再定降噪方案 |
| 本地 AI 模型算力（开发机与平板） | 模型按机器实测选型（q4/int8 小模型）；规则引擎保证 P2 不依赖模型 |
| 链路协议文档缺失（UDP 组播格式） | 桥接服务协议解析模块化，先用模拟数据开发，协议到位即插即用 |
| 云边端部署边界未定 | 开发期单机分进程模拟，服务边界按端-边-云预留，边界确认后仅改部署拓扑 |
| 瓦片数据合规 | 开发验证限 OSM 政策范围内；生产自渲染（planetiler）或合规数据源 |
| 依赖供应链 | 依赖锁定（pnpm-lock/Maven）+ 清单归档，为国产化适配备档 |
