## 1. 系统概述

### 1.1 产品定位

智能任务管理系统：面向任务指挥与无人集群协同的**平板端/桌面端浏览器访问**系统，集态势感知、AI 任务分析、集群编组、通信链路自组网、多源侦察融合、目标识别、任务决策、协同处置、效果评估于一体。三大任务模式（敏捷拒止布控 / **集群协同攻击** / 立体融合攻坚）共用 T0–T7 八阶段流程框架：T0 任务加载与场景选择 → T1 资源分组与任务编组 → T2 链路/感知建立 → T3 侦察/搜索 → T4 识别/引导 → T5 决策/处置 → T6 执行/清剿 → T7 评估/结束。

> **术语与阶段语义（据界面图订正）**：模式名统一为「集群协同攻击」（界面图中三张任务方向卡的实际用词，不写"突击攻击"）。**T0–T7 是三场景共用的编号骨架，但同名阶段的业务语义按场景不同**，见 1.2.1；需求条目中引用 T 编号时须指明场景。

系统强调：AI 语音交互（三段式：系统提示—用户语音—AI 回复）、人在回路决策（AI 推荐、用户确认）、多域协同（光电/雷达/电子/通信四类集群与战术小组、后方火力/云端算力）、前沿局部自治（断链续行）。

#### 1.2.1 三场景 T 阶段语义对照

| 阶段 | 场景一 敏捷拒止布控 | 场景二 集群协同攻击 | 场景三 立体融合攻坚 |
|---|---|---|---|
| T0 | 任务加载与场景选择 | 同左 | 同左 |
| T1 | 无人机分组与任务编组 | 无人机分组与任务编组 | **外围部署与任务编组**（资源含战术小组） |
| T2 | 通信链路建立 | **云边通信与协同链路建立** | **建筑空间感知**（结构树 + 分层展开） |
| T3 | 光电侦察展开 | 多源侦察与态势构建 | **目标搜索**（楼层/房间号定位） |
| T4 | 目标识别与筛选 | 目标识别、评估与任务生成 | **人装协同引导**（人员/无人机双路线） |
| T5 | 任务决策与打击准备 | 任务决策与打击准备 | **协同处置**（安全通道、处置窗口） |
| T6 | 协同执行与引导 | 协同执行与引导 | **区域清剿**（残余威胁分析） |
| T7 | 毁伤评估与任务结束 | 评估与任务结束 | **态势更新与任务结束**（建筑安全态势） |

**架构含义**：T 编号是**流程骨架**（阶段机、进度条、WS `mission.phase` 事件共用）；差异部分为 **① 业务对象**（无人机集群 / +战术小组 / +建筑与楼层）、**② 空间载体**（地形态势 / 云边端拓扑 / 三维建筑模型 + 楼层切换）、**③ 组件集**（场景三独有：建筑结构树、楼层切换条、二维建筑控制图、人装协同路线）。状态机转移表数据驱动、场景差异以配置注入（见风险表"状态机扩展"）。

### 1.2 技术形态总览

- **部署形态**：B/S 分布式部署、集中服务——一台主机作为**服务端**（Windows 先行），其他电脑、平板不安装任何客户端，浏览器输入内网网址操作，客户端零安装、零升级
- **服务端后端**：**C++（Drogon 框架）**——静态托管、REST API、UDP 组播接入 + WebSocket 实时推送网关、SQLite 持久化
- **AI 桥接服务**：**Python（FastAPI）**——统一接入**在线大模型 API（OpenAI 系）**：对话/方案推荐、语音识别（Whisper API）、语音合成（TTS API）
- **前端**：React + TypeScript + MapLibre GL（+deck.gl），由服务端托管、浏览器渲染；**业务状态与界面逻辑尽量前置到前端**
- **实时通道**：WebSocket 直推（C++ 网关广播到所有在线客户端），无独立消息中间件；请求响应走 REST
- **视频**：本地 H.264 mp4 文件由服务端静态托管，前端 `<video>` 直接播放——无视频网关、无转码、无远程流
- **数据**：预切北京 z3–z15 栅格瓦片服务端本地托管（流畅优先，在线源可选）；SQLite 持久化
- **客户端浏览器**：开发期 Chrome/Edge（Chromium 系）；二期国产化平板自带浏览器兼容验证
- **运行环境**：终端可联网（非断网）；重资源（地图/视频）本地化以保证流畅；非涉密，常规安全基线

## 3. 总体架构

### 3.1 逻辑架构（B/S）

```
浏览器客户端（多台电脑/平板，可联网；开发期 Chromium 系，二期国产化平板浏览器）
   │  HTTP：页面/静态资源/REST 请求（视频 mp4 直接 <video> 播放）
   │  WebSocket：实时推送（遥测/目标/阶段状态——UDP 数据的出口）
   ▼
服务端主机（一台，Windows 先行；硬件规格 ⏸）
├─ C++ 后端（Drogon）：
│   ├─ 静态托管：前端产物 + 瓦片（raster/dem/3dtiles 预留）+ 本地视频 mp4 + 报告 PDF
│   ├─ REST API：/api/v1（health、map/config、任务/目标/资源/链路/方案/报告、/ai/* 代理）
│   ├─ UDP 组播接入 → 协议解析 → WebSocket 广播（心跳失联检测）
│   └─ SQLite 持久化
└─ Python AI 桥接（FastAPI，仅本机调用）：
    ├─ /ai/chat：LLM 对话与方案推荐（OpenAI 系 API）
    ├─ /ai/stt：语音识别（Whisper API）
    └─ /ai/tts：语音合成（TTS API）
    （API Key 仅保存在服务端环境变量，不进入前端）
```

### 3.2 组件清单与职责

| 组件 | 选型 | 语言 | 运行位置 | 职责 |
|---|---|---|---|---|
| 浏览器前端 | React 19 + TS + Vite + MapLibre GL 5 + react-map-gl 8 + deck.gl 9 | TS | 客户端浏览器 | 界面、地图渲染、业务状态与流程逻辑 |

| 静态资源 | 前端产物/瓦片/视频/报告 | — | 服务端 | 本地化重资源 |

### 7.1 阶段划分总览（共 5 个阶段）

### 7.2 阶段门规则（通用）

每阶段结束时执行四步，全部通过后书面确认方可进入下一阶段；未通过项进入问题清单限期修复，不流入下一阶段：

1. **功能验收**：按本节所列需求条目（TR 编号）逐条核对
2. **非功能实测**：指标项实测（帧率/流畅度/并发等）
3. **累计回归**：上一阶段验收项重跑，防倒退
4. **演示评审**：按演示场景走查，记录问题清单

阶段内需求变更按"确认 → 回写本文档 → 同步关联文档"流程执行。

### 7.3 P0 技术基线（→ P1 门禁）
