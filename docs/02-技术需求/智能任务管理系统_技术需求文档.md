## 1. 系统概述

### 1.1 产品定位

智能任务管理系统：面向任务指挥与无人集群协同的**平板端/桌面端浏览器访问**系统，集态势感知、AI 任务分析、集群编组、通信链路自组网、多源侦察融合、目标识别、任务决策、协同处置、效果评估于一体。三大任务模式（敏捷拒止布控 / 集群协同突击攻击 / 立体融合攻坚）共用 T0–T7 八阶段流程框架（T0 任务加载与场景选择 → T1 资源分组与任务编组 → T2 通信链路/云边协同/建筑空间感知 → T3 多源侦察展开与态势构建 → T4 目标识别评估与优先级筛选 → T5 任务决策与打击/处置准备 → T6 协同执行与引导 → T7 毁伤/效果评估与任务结束）。

系统强调：AI 语音交互（三段式：系统提示—用户语音—AI 回复）、人在回路决策（AI 推荐、用户确认）、多域协同（光电/雷达/电子/通信四类集群与战术小组、后方火力/云端算力）、前沿局部自治（断链续行）。

### 1.2 技术形态总览

- **部署形态**：**分布式部署、集中服务**——一台主机作为**服务端**（Windows 先行），部署 Web 服务、业务服务、消息总线、数据存储与全部 C++ 性能模块；**其他电脑、平板不安装任何客户端**，通过浏览器输入内网网址打开网页操作，客户端零安装、零升级
- **服务端**：Java（Spring Boot）网络服务（多客户端并发），向端-边-云分级部署演进（边界暂缓）
- **前端**：React + TypeScript + MapLibre GL（+deck.gl），由服务端托管、浏览器渲染
- **C++ 性能模块**（全部部署在服务端）：视频网关（ZLMediaKit/FFmpeg）、离线语音识别/合成（sherpa-onnx/piper）、信号处理（后续）
- **内部消息总线**：MQTT（服务端 broker；前端经 MQTT over WebSocket 订阅）
- **数据**：离线地理数据（栅格瓦片/DEM）+ SQLite 起步 → PostGIS/时序库
- **客户端浏览器**：开发期 Chrome/Edge（Chromium 系）；二期验证国产化平板自带浏览器（麒麟/统信）
- **运行环境**：内网自足（无外网依赖）；非涉密，常规安全基线

## 3. 总体架构

### 3.1 逻辑架构（B/S，v2.0）

```
浏览器客户端（多台电脑/平板；开发期 Chromium 系，二期国产化平板自带浏览器）
   │  HTTP(S)：页面/静态资源/REST API（内网网址直达）
   │  MQTT over WebSocket：实时订阅（遥测/目标/链路/AI 事件）
   ▼
服务端主机（一台，Windows 先行；硬件规格 ⏸）
├─ Java Spring Boot：前端托管 + REST API + 业务/流程/持久化/规则引擎
├─ MQTT broker（NanoMQ → EMQX）：内部总线 + 前端多客户端订阅
├─ 静态资源：前端产物 + 瓦片（raster/dem/3dtiles 预留）+ 报告 PDF
├─ 数据：SQLite 起步 → PostGIS + 时序库（P4）
└─ C++ 模块（服务端部署）：
   ├─ UDP 组播桥接服务（数据链 → MQTT）
   ├─ ZLMediaKit 视频网关（H.265 → H.264 → WebRTC）
   ├─ 离线语音服务（sherpa-onnx ASR / piper TTS）
   └─ 本地 AI 推理（llama.cpp/ONNX，P3）
```

## 5. 接口与契约

### 5.1 REST API（统一前缀 `/api/v1`，JSON，向后兼容）

- 服务端监听**内网网卡**（可配置 IP/端口，默认内网 IP + 固定端口或指定端口）
- 前端与 API 同源托管，无跨域问题；访问控制预留（D15，级别 ⏸）

| 端点 | 方法 | 用途 | 阶段 |
|---|---|---|---|
| /api/v1/health | GET | 聚合健康：返回各模块子状态（地图/通信/AI/集群/数据），支撑一键自检 | P1 |
| /api/v1/map/config | GET | 底图配置（center/zoom/minZoom/maxZoom/basemap；预留 terrain、3dtiles、video、mqtt 可空字段） | P1 |
| /api/v1/scenarios · /recommend | GET · POST | 场景列表；AI 推荐场景 | P2 |
| /api/v1/missions · /{id}/phase | GET/POST · PUT | 任务生命周期与 T0–T7 阶段流转 | P2 |
| /api/v1/groups | GET/POST | 集群编组管理 | P2 |
| /api/v1/plans · /{id}/recommend | GET/POST · POST | 方案管理、AI 方案推荐 | P2 |
| /api/v1/targets · /{id} · /{id}/track · /{id}/strike | GET · GET · POST | 目标列表/详情/持续跟踪/加入打击序列 | P2 |
| /api/v1/resources/uavs | GET | 四型无人机资源状态 | P2 |
| /api/v1/links · /links/topology | GET | 链路指标与拓扑 | P2 |

## 7. 分阶段实现与验证

### 7.1 阶段划分总览（共 5 个阶段）

| 阶段 | 名称 | 核心目标 | 前置 | 粗略周期（2–3 人规模） |
|---|---|---|---|---|
| P0 | 技术基线 | **服务端 Web 基线**：单机服务端部署 + 多终端浏览器访问 + 2D 地图漫游缩放（范围与验收见 7.3） | — | 0.5–1 周 |
| P1 | 态势底座 | 地图从"能看"到"能演"：动态图层、2D/3D、消息总线、深色界面骨架、多端共享态势 | P0 验收通过 | 2–4 周 |
| P2 | 任务域 | T0–T7 全流程闭环（场景一，模拟数据）+ 规则引擎 + 多端一致性 | P1 验收通过 | 4–8 周 |
| P3 | 智能域 | 三轨：离线语音、H.265 视频 ≤0.5s、本地推理（浏览器采集 + 服务端处理） | P2 验收通过 | 6–10 周（三轨可并行） |
| P4 | 协同域 | 云边端服务端分级、断链续行、国产化浏览器兼容落地 | P3 验收通过 | 4–8 周（含真机验证） |

> 总体量级约 **4–6 个月**（2–3 人、无并行外包）。周期为粗略估算，随人力与硬件信息到位调整；每阶段末设**阶段门（Gate）**，未过门不得进入下一阶段。

### 7.2 阶段门规则（通用）

每阶段结束时执行四步，全部通过后书面确认方可进入下一阶段；未通过项进入问题清单限期修复，不流入下一阶段：

1. **功能验收**：按本节所列需求条目（TR 编号）逐条核对
2. **非功能实测**：指标项实测（帧率/延迟/内网自足/并发等）
3. **累计回归**：上一阶段验收项重跑，防倒退
4. **演示评审**：按演示场景走查，记录问题清单

阶段内需求变更按"确认 → 回写本文档 → 同步关联文档"流程执行。

### 7.3 P0 技术基线（→ P1 门禁）

- 范围：Windows 开发机单机部署服务端；多终端浏览器访问；2D 地图漫游/拖拽/缩放（北京 z3–z15 离线瓦片）；服务端启动与健康接口
- 功能验收：① 浏览器输入内网地址即显示北京地图；② 连续拖拽 30 秒无卡顿/白屏/错位；③ 滚轮缩放 z3–z15 全程流畅、中心不漂移；④ 双击放大、+/- 按钮、比例尺可用；⑤ 断外网全部交互正常且无外网请求；⑥ 重启服务后视角由 `/api/v1/map/config` 恢复；⑦ ≥2 台终端同时访问基本可用
- 附加门禁（为后续阶段铺路，随 P0 一并交付）：`/api/v1` 版本前缀落地；topic 命名规范冻结（5.2 节）；瓦片目录预留 `dem/`、`3dtiles/`；前端目录预留 `layers/`、`stores/`；依赖锁定清单

## 8. 验收准则（完整系统）

**功能验收**：以需求初稿 T0–T7 各界面交互为基准，逐条对照第 4 章需求条目验收；场景一（P2）、场景二（P4）、场景三（P2 地图部分 + P4 协同部分）分期闭环。

**非功能验收**：

| 指标 | 标准 | 验证方式 |
|---|---|---|
| 视频延迟 | 端到端 ≤0.5s | 计时对比实测 |
| 地图流畅性 | 连续拖拽/缩放无卡顿，动态图层 30 秒连续更新稳定（浏览器端） | 人工走查 + 帧率观测 |
| 内网自足 | 断外网环境全功能可用，客户端无外网请求 | 断网演练 |
| 多端并发 | 目标并发数（⏸ 暂按 5–20 台）下状态一致、操作流畅 | 多终端同屏演练 |
| 客户端兼容 | 国产化平板自带浏览器（麒麟/统信）全功能验收 | 真机测试矩阵（二期） |
| 启动与自检 | 指标待定（NFR-05） | 计时 |
| 数据口径可替换性 | 更换评分规则无需改动界面与契约 | 代码走查 + 演示 |
| 服务端备份恢复 | SQLite/报告定期备份可恢复 | 恢复演练 |

## 9. 风险与应对

| 风险 | 应对 |
|---|---|
| **语音采集 secure context**：内网 HTTP 下 Chromium 系浏览器拒绝麦克风授权 | P3 前置决策：HTTPS 自签名证书 + 客户端信任导入（推荐路径），或评估国产化浏览器策略差异；P2 末做技术验证 |
| **国产化浏览器兼容**：麒麟/统信自带浏览器内核版本、WebGL/触屏表现差异 | 开发期锁定 Chromium 系；二期真机矩阵专项验证；前端避免依赖浏览器私有特性 |
| **多客户端并发与服务端算力**：视频并发转码、遥测广播量随终端数增长 | 并发目标待定；无状态 HTTP + 广播设计；视频网关按可扩展；实测压载 |
| **服务端单点故障**：主机宕机则全部终端不可用 | 备份策略（SQLite/报告定期备份）；主备/冗余 ⏸ 按需评估 |
| **内网暴露面**：服务监听内网网卡，暴露于局域网 | 仅监听内网网卡；轻量访问控制（口令/白名单）；HTTPS 可选 |
| 视频 H.265→H.264 转码延迟与算力（≤0.5s 硬指标） | ZLMediaKit + FFmpeg 硬件编码；ultrafast 预设兜底；P3 实测校准 |
| 离线语音识别与麦克风能力未知 | sherpa-onnx 原型先行；指令集有限降低识别难度；真机验证后定降噪方案 |
| 本地 AI 模型算力（服务端机器） | 模型按机器实测选型（q4/int8 小模型）；规则引擎保证 P2 不依赖模型 |
| 链路协议文档缺失（UDP 组播格式） | 桥接服务协议解析模块化，先用模拟数据开发，协议到位即插即用 |
| 云边端部署边界未定 | 服务端按"可分级"设计，边界确认后仅改部署拓扑 |
| 瓦片数据合规 | 开发验证限 OSM 政策范围内；生产自渲染（planetiler）或合规数据源 |
| 依赖供应链 | 依赖锁定（pnpm-lock/Maven）+ 清单归档，为国产化适配备档 |
