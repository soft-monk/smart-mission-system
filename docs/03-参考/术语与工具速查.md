## 1. 语言与前端构建

| 术语 / 工具 | 是什么、干什么用 |
|---|---|
| JavaScript（JS） | 前端唯一通用的脚本语言，语法松散、动态类型。类比：Lua / Python 之于 C++ 程序——但这里是整个前端层的宿主语言 |
| TypeScript（TS） | JS 的超集，加了静态类型系统，编译成 JS 运行。类比：C++ 之于 C——"C + 类 + 模板"增强关系。本项目用它给接口契约（如地图配置）上类型保险 |
| JSX / TSX | 在 JS/TS 源码里直接写类似 HTML 的语法，编译期转换为函数调用。类比：QML / 声明式模板语法；`.tsx` = 含 JSX 的 TS 文件 |
| Node.js | 让 JS 脱离浏览器、在操作系统里独立运行的运行时（自带 V8 引擎 + 系统 API）。前端构建链与服务端工具链都基于它。类比：一个独立的脚本运行平台（如嵌了 LuaJIT 的宿主进程） |
| npm | Node 生态的官方包管理器与注册中心（npmjs.com），负责下载依赖。类比：vcpkg / Conan |
| pnpm | 另一种包管理器，硬链接共享依赖、省磁盘、monorepo 支持好（模板仓库就用它）。类比：Conan 2 的缓存共享 |
| Vite | 前端构建工具 + 开发服务器：开发时秒级热更新，发布时打包压缩产物。类比：CMake + 编译器 + 本地运行循环的合体；"dev proxy"是其内置的请求转发（类比：本地端口转发/反向代理） |
| React | 声明式 UI 组件框架，界面由"组件树"构成，数据变化自动重渲染。类比：Qt Widgets 的地位；React 组件 ≈ 自定义 Widget |
| React Hooks | React 里封装"状态 + 副作用"的函数式写法（如 `useState`、`useEffect`）。类比：把信号槽 + 生命周期管理封装成可复用工具函数；模板的 `use-maplibre` 就是把地图实例封装成 hook |
| Storybook | 组件开发与预览工作台：每个 UI 组件单独陈列、可交互演示。类比：组件库的"演示台/样例浏览器"，本项目建议二期引入 |
| monorepo | 一个 Git 仓库装多个可独立发布的包，统一构建。类比：一个大仓库多个 target/子项目 |
| npm 包 | JS 生态的最小发布单元（一个包 = 一组源码 + `package.json` 清单）。类比：一个发布到 vcpkg 的库 |
| Apache-2.0 | 开源许可证：允许商用、修改、闭源使用，需保留版权声明。模板仓库即此协议 |
| zod | JS 运行时数据校验库：对接口返回的 JSON 做"形状+类型"校验再使用。类比：反序列化后先做 schema 校验，防止脏数据进入业务逻辑 |
| JSDoc + checkJs | 不写 `.ts` 文件但保留类型检查的折中：用 `/** */` 注释标注类型，编辑器据此检查普通 JS。类比：给动态语言加"轻量类型标注" |

## 2. 地图与地理

| 术语 / 工具 | 是什么、干什么用 |
|---|---|
| WebGL | 浏览器内的 GPU 图形接口（基于 OpenGL ES）。MapLibre 用它渲染地图。类比：桌面 OpenGL；不支持 WebGL 的环境才需要 Leaflet 兜底 |
| MapLibre GL JS | 开源地图渲染引擎（BSD 协议，Mapbox GL JS v1 的分支），**免 API token**；内置拖拽、滚轮缩放、双击、触屏手势。类比：地图领域的"渲染引擎 SDK"（类似用 Qt Location，但纯前端） |
| react-map-gl | React 与 MapLibre 之间的适配层，把命令式地图 API 包装成 React 组件。类比：C++ 里给引擎 SDK 套的一层门面（facade） |
| deck.gl | 高性能大数据可视化框架（visgl 出品），在地图之上叠加海量矢量图形。类比：额外的"叠层渲染引擎"；本项目 P1 引入 |
| turf | JS 地理空间计算库（距离、缓冲、判断点在面内等）。类比：Boost.Geometry / GEOS 的 JS 版 |
| Leaflet | 极轻量（约 42KB）的地图库，用 DOM/SVG 渲染、**不依赖 WebGL**，只吃栅格瓦片。类比：纯 2D 位图式渲染的 fallback 方案 |
| 栅格瓦片 | 把地图**预渲染成图片**（PNG），按层级/行列切片存储；放大时先显示模糊低层级再替换高清。类比：超大地图的 mipmap 金字塔，每块 256×256 |
| 矢量瓦片 | 不存图片，存几何数据（点线面 + 属性），由客户端实时渲染；效果好但需自托管样式/字体/图标。本项目二期选项 |
| XYZ 目录 / `{z}/{x}/{y}.png` | 瓦片文件的编号约定：z=层级，x=列号，y=行号（左上角为原点）。类比：资源文件的路径索引约定 |
| zoom level（z3–z15） | 缩放层级：全球在 z 层被切成 `2^z × 2^z` 张瓦片，每升一级瓦片数 ×4。本项目切北京 z3–z15（z15 最精细，z3 概览） |
| bbox | 边界框（bounding box）：`[最小经度, 最小纬度, 最大经度, 最大纬度]`。类比：AABB。文档中 `116.05–116.75°E, 39.70–40.15°N` 即北京城区范围，用于限定切片区域 |
| 经纬度（lng / lat） | 地理坐标：经度（东西，-180~180）、纬度（南北，-90~90）。文档 center=[116.39, 39.90] 即北京中心（天安门附近） |
| WGS84（EPSG:4326） | 全球大地坐标系，GPS 所用；Web 上数据（GeoJSON 等）的标准坐标系。类比：统一的世界坐标系 |
| Web Mercator（EPSG:3857） | 把球面投影到平面（正方形世界）的坐标系统，**所有 Web 瓦片都按它切**；MapLibre 自动完成 4326→3857 投影。类比：3D→2D 投影后的屏幕坐标约定 |
| EPSG | 全球坐标系/投影的编号注册表（European Petroleum Survey Group 维护）。类比：坐标系命名的国际标准库 |
| GCJ-02 | 中国国测局加密坐标：在 WGS84 上人为加偏移（可达数百米），高德/腾讯等国内地图使用。类比：加扰后的坐标，需专用算法还原 |
| BD-09 | 百度在 GCJ-02 之上再加一次偏移。本项目"全球通用"路线**不涉及** GCJ-02/BD-09 |
| CGCS2000 / 天地图 | CGCS2000：中国 2000 大地坐标系（与 WGS84 厘米级一致，**无偏移**）；天地图：国家官方地图服务平台（需申请 key）。二期若需国内详图可接入 |
| GeoJSON | 地理矢量数据的 JSON 交换格式（RFC 7946）：点/线/面 + 属性。类比：通用序列化交换格式 |
| raster style | MapLibre 的样式 JSON：声明数据源类型为栅格（raster）+ 瓦片 URL 模板。类比：渲染管线的"材质/资源描述文件" |
| attribution（版权标注） | 数据源要求署名的声明，显示在地图右下角。OSM 的**法定义务**，不能去掉 |
| OpenStreetMap（OSM） | 全球协作的开源地图数据。类比：开源地图数据集社区（类似"维基地图"） |
| Geofabrik | OSM 数据的区域提取下载站（提供 pbf 二进制格式）。类比：数据镜像站 |
| planetiler | 把 OSM 提取数据离线转成瓦片包（mbtiles/pmtiles）的快速工具（Java 实现）。类比：离线"烘焙/预处理管线"，生产合规路线 |
| OpenMapTiles | 开源矢量瓦片的标准 schema 与生成工具集，配合 planetiler 出矢量瓦片 |
| QGIS | 开源桌面 GIS 软件；本方案用它当"切图 GUI"：加载 OSM 图层后一键导出 XYZ 瓦片目录，免写抓取脚本 |
| OSM Tile Usage Policy | OSM 公共瓦片服务器的使用政策：**禁止批量抓取**，仅限开发验证、不得对外分发；生产必须自渲染或用合规源 |
| MGRS / GARS / milSymbol | 军用地图网格标准与军标符号库；模板 `map-toolkit` 的国防向能力，本项目**明确不引入** |

## 3. Java 后端

| 术语 / 工具 | 是什么、干什么用 |
|---|---|
| JDK | Java 开发工具包：编译器 javac + 标准库 + 工具（含 jlink/jdeps）。类比：完整工具链 SDK |
| JRE | Java 运行时：只含运行程序所需的部分。**Java 9 起官方不再单独发布 JRE**，服务端直接装 JDK 或按需裁剪 |
| jlink | JDK 自带工具：按需生成裁剪版 JRE（只含程序用到的模块，约 40–60MB）。服务端环境可控，为**可选**工具。类比：从完整工具链里拼一个最小运行时（类似裁剪 VC++ 运行库） |
| jdeps | 分析 class 文件依赖哪些 JDK 模块的工具，jlink 裁剪的依据。类比：链接依赖分析（ldd/nm 的意图） |
| Maven | Java 的构建 + 依赖管理工具（`mvn package` 编译打包）。类比：CMake + vcpkg 合体 |
| fat-jar | Spring Boot 打包出的"全量可执行 jar"：所有依赖塞进一个文件，`java -jar xxx.jar` 直接跑。类比：全静态链接的单二进制 |
| BOOT-INF | fat-jar 内部存放依赖与资源的目录名 |
| Spring Boot | Java 后端框架：内嵌 Web 服务器（Tomcat）、自动装配、约定优于配置。类比：batteries-included 的 Web 服务框架 |
| Controller | Spring 里处理 HTTP 请求的类（`@RestController`），对应文档中的 `HealthController`、`MapConfigController`。类比：请求处理/路由入口 |
| application.yml | Spring Boot 的 YAML 配置文件（监听地址/端口、地图配置等都在这里）。类比：.ini/.json 配置 |
| 静态资源 / static 目录 | 无需处理、原样返回的文件（前端产物 HTML/JS、瓦片 PNG）。类比：Web 服务器文档根目录 |
| WebMvcConfigurer | Spring 里定制资源映射的接口：把磁盘目录（如 `tiles/`）挂到 URL 路径（`/tiles/**`）上。类比：注册一个自定义路由/挂载点 |
| 回环地址（127.0.0.1 / localhost） | 只在本机内部通信的地址，数据不出网卡。服务端业务流量走内网网卡，回环供本机管理端口使用 |
| 健康检查 | 服务端 `/api/v1/health` 返回各模块子状态，浏览器端自检页面据此聚合展示。类比：watchdog 循环 |
| REST / GET / JSON | REST：以资源为中心的接口风格；GET：HTTP 的"读"方法；JSON：数据格式（键值 + 数组）。类比：约定的 RPC 风格 + 结构化序列化 |
| HTTP 状态码 | 响应结果的数字代号（200=成功，500=服务器错误等）。文档中接口正常返回即 200 |

## 4. 接口参数逐字段说明

### 4.1 `GET /api/v1/health` —— 健康检查

| 字段 | 含义 |
|---|---|
| status | 固定返回 `"ok"`，表示服务端已就绪；自检页面据此聚合各模块状态 |
| version | 应用版本号字符串（如 `1.0.0`），供排查与版本信息展示 |

### 4.2 `GET /api/v1/map/config` —— 地图初始化配置

| 字段 | 类型 | 含义 |
|---|---|---|
| center | `[number, number]` | 初始地图中心点，`[经度, 纬度]`（WGS84）。例 `[116.39, 39.90]` = 北京天安门附近 |
| zoom | `number` | 初始缩放层级（11 ≈ 城区街道级） |
| minZoom | `number` | 允许缩到的最粗层级（3 = 大区域概览，与切片下限一致） |
| maxZoom | `number` | 允许放大的最细层级（15 = 街道级，与切片上限一致；超过会看不到瓦片，所以两者必须匹配） |
| basemap.type | `"raster"` | 底图类型固定为栅格（图片瓦片） |
| basemap.tiles | `string[]` | 瓦片 URL 模板数组；`{z}/{x}/{y}` 是**占位符**，地图库会按"层级/列/行"自动替换后去取对应 PNG。例 `/tiles/{z}/{x}/{y}.png` → 实际请求 `/tiles/15/26888/12436.png` |
| basemap.tileSize | `number` | 单张瓦片的像素边长（标准 256） |
| basemap.attribution | `string` | 版权署名文本，必须显示在界面右下角（OSM 的合规义务） |

### 4.3 边界参数（切片范围）

| 参数 | 含义 |
|---|---|
| `116.05–116.75°E` | 北京 bbox 经度范围（东经 116.05° 到 116.75°，约 60km 宽） |
| `39.70–40.15°N` | 北京 bbox 纬度范围（北纬 39.70° 到 40.15°，约 50km 高） |
| `z3–z15` | 切片层级范围：z15 共约 2,600 张，累计约 3,500 张、数十 MB；z16 单独就要约 1 万张，默认不切 |

## 5. 命令与启动参数速查

| 命令 / 参数 | 干什么用 |
|---|---|
| `pnpm build` | 构建前端（Vite 打包 React 页面产物） |
| `mvn package` | 构建后端（Maven 编译 + 打 fat-jar） |
| `java -jar backend\mapapp.jar` | 服务端启动命令（服务端主机上执行） |
| `server.address=<内网IP>` | 配置项：绑定内网网卡（默认按需收紧为指定网卡） |
| `server.port=<端口>` | 配置项：服务端固定端口（客户端浏览器访问地址的一部分） |
| `{z}/{x}/{y}.png` | 瓦片文件路径约定：z=层级目录，x=列号文件，y=行号文件（详见第 2 章 XYZ 条目） |
| Vite dev proxy | 开发期把页面的 `/api`、`/tiles` 请求转发到本地服务端（生产期不需要，页面与 API 同源托管） |
| DevTools Network | Chromium 开发者工具的网络面板，用来核对"无外网请求"——类比：本页面级的抓包工具 |

## 6. 一句话总结本方案的非 C++ 技术地图

```
客户端：任意浏览器（输入内网网址，零安装）——开发期 Chrome/Edge，二期国产化平板浏览器
  界面：React + TypeScript + Vite（组件化 UI + 静态类型）
    地图：react-map-gl + MapLibre GL（WebGL 渲染引擎）
      数据：服务端托管的离线栅格瓦片 XYZ（预烘焙图片金字塔）
  实时：mqtt.js（MQTT over WebSocket，订阅服务端广播）
服务端：一台主机集中部署
  Web/业务：Spring Boot fat-jar（内嵌服务器，托管前端 + API + 瓦片）
    消息：MQTT broker（NanoMQ/EMQX，内部总线 + 多端广播）
    C++ 模块：UDP 组播桥接 · 视频网关（ZLMediaKit/FFmpeg）· 离线 ASR/TTS · 本地推理
    数据：SQLite → PostGIS/时序库；报告 PDF 落服务端目录
```

C++ 工程师最小认知集：**B/S=服务端集中+浏览器访问、React=UI 组件化、MapLibre=地图渲染引擎、Spring Boot=内嵌服务器后端、MQTT=内部消息总线、瓦片=预渲染图片金字塔**，其余条目随用随查即可。
