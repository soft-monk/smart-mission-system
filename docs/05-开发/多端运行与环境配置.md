# 多端运行与环境配置（换机指南）

> 目标：**任何一台 Windows 机器 clone 之后，三步跑起来；每台机器的差异只写在一个本地文件里**（`scripts\env.local.bat`，不入库），从此不再改共享脚本。
> 相关脚本：`scripts\doctor.bat`（体检）、`scripts\setup_env.bat`（一次性准备）、`scripts\build_all.bat`（构建）、`scripts\start_all.bat`（启动）。

---

## 1. 三步跑通

在 **cmd**（不是 PowerShell）里，于仓库根目录执行：

```bat
scripts\doctor.bat        :: 1) 体检：缺什么、怎么补，一目了然
scripts\setup_env.bat     :: 2) 一次性：建 ai\.venv + 装 Python 依赖 + npm install
scripts\build_all.bat     :: 3) 构建：前端产物 -> backend\static，C++ -> backend\bin\Release\mapapp.exe
scripts\start_all.bat     :: 4) 启动：AI 桥 + 后端；浏览器打开 http://127.0.0.1:8080/
scripts\stop_all.bat      ::    停止
```

首次在全新机器上，若 `doctor.bat` 报 vcpkg 缺失：

```bat
scripts\install_vcpkg.bat   :: 克隆并引导 vcpkg（默认装到 %USERPROFILE%\vcpkg）
```

> **为什么用 cmd 而不是 PowerShell**：Windows 默认执行策略禁止运行 `npm.ps1`，在 PowerShell 里直接敲 `npm` 会报 `running scripts is disabled on this system`。批处理调用的是 `npm.cmd`，不受影响。若你坚持用 PowerShell，请先 `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`。

## 2. 环境变量（宏）清单

优先级：**命令行参数 > 环境变量 > `config.json` > 内置默认值**。

### 2.1 脚本侧（由 `scripts\env.bat` 自动探测导出）

| 变量 | 作用 | 默认/探测顺序 |
|---|---|---|
| `MAPAPP_ROOT` | 仓库根目录（绝对路径） | 由脚本自身位置推导 |
| `MAPAPP_CMAKE` | cmake.exe | env.local → `PATH` → `vswhere` 查到的 VS 自带 CMake |
| `MAPAPP_CMAKE_GENERATOR` | CMake 生成器 | 留空＝由 CMake 自动选择（推荐） |
| `MAPAPP_VCPKG_ROOT` | vcpkg 目录 | env.local → `VCPKG_ROOT` → `C:\vcpkg`、`D:\vcpkg`、`%USERPROFILE%\vcpkg`、`%LOCALAPPDATA%\vcpkg`、`C:\dev\vcpkg`、`D:\dev\vcpkg`、`C:\tools\vcpkg` |
| `MAPAPP_VCPKG_TOOLCHAIN` | `vcpkg.cmake` 路径 | 由 `MAPAPP_VCPKG_ROOT` 推导 |
| `MAPAPP_PYTHON` | Python 启动器 | env.local → `py -3.12` → `3.11` → `3.13` → `3.10` → `py -3` → `python` |
| `MAPAPP_NODE` | node.exe | env.local → `PATH` |
| `MAPAPP_HTTP_PORT` | 后端端口 | 8080 |
| `MAPAPP_AI_PORT` | AI 桥端口 | 8090 |

脚本还会**清空** `HTTP_PROXY/HTTPS_PROXY/http_proxy/https_proxy/NO_PROXY/no_proxy/NODE_USE_ENV_PROXY`：当大小写两个 `NO_PROXY` 同时存在时，.NET 环境字典会抛"已添加项"，直接导致 MSBuild/CL.exe 失败。

### 2.2 后端读取（C++ 服务端，`Config::applyEnv()`）

| 变量 | 作用 | 对应 config.json 键 |
|---|---|---|
| `MAPAPP_LISTEN_ADDR` | 监听地址 | `listenAddr` |
| `MAPAPP_HTTP_PORT` | 监听端口 | `listenPort` |
| `MAPAPP_THREAD_NUM` | 工作线程数 | `threadNum` |
| `MAPAPP_AI_HOST` / `MAPAPP_AI_PORT` | AI 桥地址（反代目标） | `aiBridgeHost` / `aiBridgePort` |
| `MAPAPP_UDP_GROUP` / `MAPAPP_UDP_PORT` | UDP 组播地址/端口 | `udpGroup` / `udpPort` |
| `MAPAPP_UDP_ENABLED` | 是否接收组播 | `udpEnabled` |
| `MAPAPP_NODE_TIMEOUT_MS` | 失联判定超时 | `nodeTimeoutMs` |
| `MAPAPP_STATIC_DIR` / `MAPAPP_TILES_DIR` / `MAPAPP_MEDIA_DIR` / `MAPAPP_REPORTS_DIR` | 静态目录 | 同名键 |
| `MAPAPP_DB_PATH` / `MAPAPP_SCENARIOS_DIR` | 数据库与场景目录 | 同名键 |
| `MAPAPP_MAP_LNG` / `MAPAPP_MAP_LAT` / `MAPAPP_MAP_ZOOM` / `MAPAPP_MAP_MIN_ZOOM` / `MAPAPP_MAP_MAX_ZOOM` | 地图默认视角 | 同名键 |
| `MAPAPP_SIM_ENABLED` / `MAPAPP_SIM_INTERVAL_MS` | 内置遥测模拟器 | 同名键 |

命令行参数（可选）：`mapapp.exe [--config <path>] [--host <addr>] [--port <n>] [--help]`

### 2.3 AI 桥（Python）

| 变量/参数 | 作用 |
|---|---|
| `OPENAI_API_KEY` | 在线大模型/语音 API Key（**优先于 `ai\config.json` 的 `apiKey`**，推荐只放环境变量） |
| `--host` / `--port` / `--log-level` | 覆盖 `ai\config.json` 的监听与日志 |
| `MAPAPP_TILE_PROXY` | 仅 `scripts\fetch_tiles.py` 用：抓瓦片时显式走代理（如 `http://127.0.0.1:7897`） |

## 3. 换机指南（只改一个文件）

1. clone 仓库，执行 `scripts\doctor.bat` 看体检结果
2. 若有 `[MISS]`：
   - **vcpkg 缺失** → `scripts\install_vcpkg.bat`
   - **CMake/Python/Node 不在 PATH** → 正常安装，或在下一步里指定
3. 按需复制覆盖文件：

   ```bat
   copy scripts\env.local.bat.example scripts\env.local.bat
   ```

   然后在 `env.local.bat` 里只保留这台机器的差异，例如：

   ```bat
   set "MAPAPP_VCPKG_ROOT=D:\dev\vcpkg"
   set "MAPAPP_HTTP_PORT=18080"
   set "MAPAPP_AI_PORT=18090"
   set "MAPAPP_PYTHON=py -3.12"
   ```

4. `scripts\doctor.bat` 全绿 → `scripts\setup_env.bat` → `scripts\build_all.bat` → `scripts\start_all.bat`

`scripts\env.local.bat` 已在 `.gitignore` 中，**永远不会被提交**，所以每台机器的路径差异不会互相干扰。

## 5. 首次构建要下载什么（国内网络排障）

首次 `build_all.bat` 会让 **vcpkg 从源码编译 drogon 及其依赖**（openssl、trantor、jsonrpc、c-ares、brotli、zlib、sqlite3 等）。
实测：**依赖编译约 12 分钟**（openssl 6 分钟、drogon 3 分钟，其余各 10–30 秒），后端本体编译约 10 秒。
之后的增量构建只需十几秒。

在这之前，vcpkg 自己还会下载几个**较大的辅助工具**，国内直连 GitHub 容易超时（curl error 56 / 35）：

| 文件 | 大小 | 用途 | vcpkg 缓存位置 |
|---|---|---|---|
| `cmake-4.4.2-windows-x86_64.zip` | 52 MB | vcpkg 构建端口用的 CMake（系统 CMake 版本不足时） | `%USERPROFILE%\vcpkg\downloads\` |
| `PowerShell-7.6.4-win-x64.zip` | 112 MB | 部分 portfile 的脚本宿主 | 同上 |
| `strawberry-perl-5.42.2.1-64bit-portable.zip` | 290 MB | openssl 构建所需 Perl | 同上 |
| `nasm-3.01-win64.zip` / `jom_1_1_7.zip` / msys2 包 | 小 | 汇编器 / 并行构建 / pkgconf | 同上 |

**两条处理路径（任选）**：

1. **走代理**（推荐，本机已配置）：在 `scripts\env.local.bat` 里加

   ```bat
   set "MAPAPP_HTTPS_PROXY=http://127.0.0.1:7897"
   set "MAPAPP_HTTP_PROXY=http://127.0.0.1:7897"
   ```

   `env.bat` 会把它重新注入为标准的 `HTTP(S)_PROXY`，vcpkg/pip/npm/git 都会使用它。
   注意：本机实测 ArcGIS 瓦片源**拒绝代理**（403），抓瓦片时要直连。

2. **手动预下载到缓存**（代理也不稳时）：文件名必须与 vcpkg 期望的一致，断点续传可反复重试：

   ```bat
   curl -L -C - --proxy http://127.0.0.1:7897 -o "%USERPROFILE%\vcpkg\downloads\<文件名>" <url>
   ```

   vcpkg 发现缓存命中后会直接解压，不再联网。

## 6. 瓦片数据（地图底图）

仓库不含瓦片（二进制不入库）。首次需要抓一次：

```bat
py -3.12 scripts\fetch_tiles.py
```

- 数据源：Esri World Imagery（免 Key），覆盖 world z0–6 + 北京 z7–14 + 上海 z7–13，约 1.3 万张、百 MB 级
- **直连可用**（实测 200，约 15 KB/张、0.8 s）；走代理会被源站 403，因此脚本默认直连
- 脚本幂等：已存在的瓦片自动跳过，中断后重跑即可续传
- 缺瓦片不影响启动：地图会走 `fallback: solid` 纯色底，界面其余功能正常
- 需要代理时（某些网络环境才需要）设 `MAPAPP_TILE_PROXY=http://127.0.0.1:7897`

## 7. 常见故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 命令输出乱码 | 批处理输出中文，而 cmd 默认代码页是 GBK | 已修复：所有 `.bat` 改为**纯 ASCII 英文输出**；C++/Python 进程经 `run_server.bat` / `run_bridge.bat` 包装，内部 `chcp 65001` |
| `npm : 无法加载文件 npm.ps1，因为在此系统上禁止运行脚本` | PowerShell 执行策略 | 在 cmd 里跑脚本，或 `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` |
| `CMake Error: ... vcpkg.cmake not found` | 机器上没有 vcpkg（旧脚本硬编码 `C:/vcpkg`） | `scripts\install_vcpkg.bat`，或在 `env.local.bat` 里设 `MAPAPP_VCPKG_ROOT` |
| `MSB6006 / cl.exe 已退出，代码为 -1073741515` | 环境里存在大小写重复的 `NO_PROXY` | 已修复：`env.bat` 统一清空代理变量 |
| 启动后日志文件找不到 / 无法写日志 | `backend\data` 目录不存在（旧脚本直接重定向） | 已修复：`run_server.bat` / `start_all.bat` 自动创建 `data`、`data\reports` |
| 端口被占用（8080/8090） | 本机已有服务在监听 | `start_all.bat` 会**预检并打印占用者 PID/镜像名**且不启动：残留 mapapp → 跑 `scripts\stop_all.bat`；其他程序 → 在 `env.local.bat` 改 `MAPAPP_HTTP_PORT` / `MAPAPP_AI_PORT`（脚本与后端都会跟随） |
| **停止服务时误杀了别的程序**（编辑器、代理、其他 Web 服务等） | 旧版 `stop_all.bat` 按「窗口标题」匹配，且端口变量为空时 `findstr ":"` 会匹配**所有**监听端口 | 已修复：端口先做数字校验（非法即回退 8080/8090）；只按「端口 → PID」定位，且必须**同时**满足镜像名（mapapp.exe / python.exe / pythonw.exe）与（python 的）命令行路径在本仓库内才 kill；**按窗口标题杀进程的逻辑已彻底移除**；`start_all.bat` 绝不杀任何进程 |
| `py -3` 版本过新导致 pip 装包失败 | 例如只装了 3.14，部分依赖轮子未发布 | `env.bat` 已优先选择 3.12/3.11/3.13/3.10；也可在 `env.local.bat` 固定 `MAPAPP_PYTHON` |
| CMake 选了错误的 VS / 生成器 | 机器上有多个 VS 版本 | 在 `env.local.bat` 设 `MAPAPP_CMAKE_GENERATOR=Visual Studio 17 2022` |
| AI 相关接口返回 `code=2001` | AI 桥未启动或未配 Key | 启动 `scripts\start_all.bat`；把 `OPENAI_API_KEY` 放进环境变量 |

## 8. 脚本清单

| 脚本 | 用途 |
|---|---|
| `scripts\env.bat` | 共享环境探测（无输出，被其他脚本 `call`） |
| `scripts\env.local.bat.example` | 机器本地覆盖模板（复制为 `env.local.bat` 后生效） |
| `scripts\doctor.bat` | 环境体检：逐项 OK/MISS + 修复指引 |
| `scripts\install_vcpkg.bat` | 一次性安装 vcpkg（仅缺失时需要） |
| `scripts\setup_env.bat` | 一次性准备：Python venv + 依赖 + npm install |
| `scripts\build_all.bat` | 构建前端 + C++ 后端 |
| `scripts\start_all.bat` | 启动 AI 桥 + 后端（新窗口，日志落 `backend\data\`） |
| `scripts\stop_all.bat` | 停止两个服务（按窗口标题与端口双保险） |
| `backend\build_release.bat` | 只构建 C++（缺 `build\CMakeCache.txt` 时自动配置） |
| `backend\run_server.bat` | 前台运行后端（自动建目录、写日志、`chcp 65001`） |
| `ai\run_bridge.bat` | 运行 AI 桥（缺 venv 时自动创建并装依赖） |
