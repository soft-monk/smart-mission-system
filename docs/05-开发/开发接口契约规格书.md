# 开发接口契约规格书（v1.0 · 全量开发基准）

> 本文件是全量开发的**唯一接口基准**，由后端（C++）、前端（TS）、AI 桥（Python）三方共同遵守。
> 上游依据：`docs/01-需求/智能任务管理系统_界面需求初稿.md`、`docs/02-技术需求/智能任务管理系统_技术需求文档.md`(v1.2)、`docs/04-设计/概要设计文档.md`(v1.2)。
> 冲突时以本文档为准（本文档是对上游未定项作出明确取值的地方）；改契约必须先改本文件。

## 0. 范围与形态（v1.2 收敛后）

- **两个场景**：场景一 `scenario-1` 敏捷拒止布控；场景二 `scenario-2` 集群协同攻击。
- **仅二维渲染**：MapLibre GL flat + WebGL 平面，**无 2D/3D 切换、无三维地形、无三维建筑**。
- 场景三与全部三维能力已放弃，**不得实现**（见需求初稿附录 A/B）。
- 交付形态：浏览器多终端（平板横屏优先），客户端零安装。

## 1. 端口与运行时（TRD D14/T5 未定项的取值）

| 项 | 取值 | 说明 |
|---|---|---|
| 后端 HTTP/WS 端口 | `8080` | `config.json` 可改；监听内网网卡（默认 0.0.0.0 便于开发） |
| Python AI 桥 | `127.0.0.1:8090` | **仅本机**，由 C++ 反代 `/api/v1/ai/*` |
| UDP 组播（遥测） | `239.10.10.10:45454` | 组播接收；开发用 `telemetry_sim` 工具发送 |
| UDP 遥测序列化 | JSON（UTF-8 单包 ≤ 8KB） | 链路协议文档缺失，先以 JSON 模拟；Parser 接口隔离，协议到位替换 |
| SQLite | `data/mapapp.db` | 服务端本地文件 |
| 静态资源 | `/`、`/tiles/**`、`/media/**`、`/reports/**` | Range 请求支持 |
| 设计基准分辨率 | **1920×1080（横屏）** | UI-07 取值；弹性布局 + 等比缩放，最小可用 1280×800 |

## 2. 统一约定

- REST 前缀 `/api/v1`，统一响应体：
  ```json
  { "code": 0, "message": "ok", "data": { } }
  ```
  `code=0` 成功；非 0 为错误，`message` 给人类可读原因。HTTP 状态码仍语义化（200/400/404/500）。
- 时间：ISO-8601 本地字符串 `YYYY-MM-DD HH:mm:ss`；时间戳 `ts` 为 **epoch 毫秒**。
- ID：`missions`/`targets` 等业务实体用字符串 ID；目标另有任务内唯一 `target_no`（整数）。
- 所有写操作幂等设计（重复提交返回同结果或 `code=1001 已执行`）。
- 关键确认类动作服务端**互斥**：后到者返回 `code=1002 正在执行/已执行`（TRD BIZ-12）。

## 4. WebSocket 契约

- 端点 `ws://<host>:8080/ws`；单通道；消息体 `{ "type": "...", "data": {...}, "ts": 1700000000000 }`
- 客户端 → 服务端：仅 `{ "type":"ping" }`；服务端回 `{ "type":"pong" }`（心跳 15s，超时 45s 踢除）
- 订阅：连接即订阅全部事件（TRD MSG-01），无需订阅报文。

| type | 方向 | data 关键字段 |
|---|---|---|
| `telemetry.uav.pos` | S→C | `{ uavId, groupId, type, lng, lat, alt, heading, speed, battery, ts }` |
| `telemetry.uav.status` | S→C | `{ uavId, online, battery, signal }` |
| `telemetry.link.quality` | S→C | `{ linkId, from, to, signal, bandwidthMbps, latencyMs, lossRate, coverageKm2, meshProgress, state:"green"\|"yellow"\|"red" }` |
| `target.state` | S→C | `{ targetId, targetNo, threat, confidence, dynamicState, lng, lat, status:"red"\|"yellow"\|"gray" }` |
| `mission.phase` | S→C | `{ missionId, phase:"T0".."T7", scenarioKey, progress, prevPhase }` |
| `mission.progress` | S→C | `{ missionId, progress, phase, label, done, total }` |
| `plan.state` | S→C | `{ missionId, side:"group"\|"strike", planId, action:"generated"\|"recommended"\|"adopted"\|"optimized"\|"confirmed", recommendedId }` |
| `resource.uav.state` | S→C | `{ missionId, totals:{optical,radar,electronic,comm}, available, allocated, pending, onlineRate }` |
| `ai.recommendation` | S→C | `{ scene, planId?, text, provider, recommendedId? }` |
| `ai.event` | S→C | `{ level:"info"\|"warn"\|"critical", title, text, speak:true, highlight?:{type,lng,lat} }` |
| `voice.state` | S→C | `{ state:"idle"\|"speaking"\|"listening"\|"recognizing"\|"acting", text? }` |
| `alert` | S→C | `{ level, code, title, text }` |
| `node.state` | S→C | `{ nodeId, name, online, lastSeen }` |
| `pong` | S→C | `{}` |

## 5. 数据模型（SQLite 表）

| 表 | 关键列 |
|---|---|
| `scenario` | key(PK), name, subtitle, features, region, recommended, sort |
| `mission` | id(PK), scenario_key, task_no, task_name, task_type, task_region, source, phase, status, progress, received_at, started_at, finished_at, duration_sec |
| `uav` | id(PK), mission_id, type(optical/radar/electronic/comm), group_id, total_no, status, battery, lng, lat, alt, online |
| `uav_resource` | mission_id(PK), type, total, available, allocated, pending, ability_tags |
| `group` | id(PK), mission_id, plan_id, seq, name, optical, radar, electronic, comm, task_dir, cover_area, task_attr, coop_rel, readiness |
| `target` | id(PK), mission_id, target_no, name, type, threat(high/mid/low), confidence, lng, lat, alt, source, dynamic_state, status(red/yellow/gray), strike_priority, value_tag, upgraded |
| `target_track` | id, target_id, ts, lng, lat, speed, heading |
| `link` | id(PK), mission_id, from_node, to_node, signal, bandwidth_mbps, latency_ms, loss_rate, coverage_km2, mesh_progress, state |
| `link_metric_curve` | id, mission_id, kind(bandwidth/latency), ts, value |
| `plan` | id(PK), mission_id, side(group/strike), seq, name, subtitle, method, groups, success_rate, effect, stars, recommended, reason, advantage, note, adopted, confirmed |
| `assessment` | mission_id(PK), total_damage_rate, destroyed, severe, damaged, intact, area_control, effect_metrics(json) |
| `target_result` | id, mission_id, target_id, result(destroyed/severe/damaged/intact) |
| `mission_metrics` | mission_id(PK), coverage_rate, targets_found, coop_efficiency, link_stability, mesh_duration_sec, alert_count, resource_used(json), survival_rate |
| `report` | id(PK), mission_id, report_no, path, created_at |
| `event_log` | id, mission_id, type, payload, ts （事件溯源/断链续行预留） |

> `target` 唯一约束：`UNIQUE(mission_id, target_no)`。

## 7. 界面文案（必须与需求初稿逐字一致）

### 7.1 启动与自检
- 系统名：`智能任务管理系统`；副标题：`系统启动中，请稍候…`；底部：`系统启动中，正在初始化核心模块…`
- 模块加载：`地图引擎`、`通信链路`、`AI引擎`、`集群管理`、`数据服务`
- 系统状态：`网络连接/在线`、`数据链路/稳定`、`GPS定位/正常`、`系统安全/安全`
- 自检页：标题`系统状态自检`，副标题`请确认系统状态，确保各模块正常运行`，按钮`一键自检`，底部`自检过程预计耗时 15~30 秒`

## 10. 实现备注（全量开发实测，2026-09-10）

本节记录实现中确认的取值与踩坑，供后续维护参考。

### 10.1 环境坑（已规避，勿回退）

1. **`NO_PROXY` / `no_proxy` 大小写重复键**：Windows 环境块大小写不敏感，但 .NET 的
   `ProcessStartInfo.EnvironmentVariables` 是大小写敏感的 Hashtable。两者同时存在时
   MSBuild/CL.exe 会因“已添加项”直接失败。→ 所有构建/启动脚本
   （`scripts\*.bat`、`backend\build_release.bat`、`backend\run_server.bat`）
   先清空这些变量再调用工具链。
2. **`no_proxy` 含 `[::1]`**：`httpx` 建客户端时会把它当 URL 解析并抛
   `InvalidURL: Invalid port: ':1]'`，导致 AI 桥启动失败。→ `ai/bridge.py` 的两处
   `httpx.AsyncClient` 均设 `trust_env=False`，不再读取代理环境变量。

### 10.2 实测确认的取值

| 项 | 取值 | 说明 |
|---|---|---|
| 后端监听 | `0.0.0.0:8080` | 便于局域网平板演示 |
| AI 桥 | `127.0.0.1:8090` | 仅本机，C++ 反代出口 |
| UDP 组播 | `239.10.10.10:45454` | 无外部源时内置模拟器 1s 周期推送 |
| 前端产物 | `backend/static` | 由 Drogon `setDocumentRoot` 托管 |
| SPA 回落 | 仅匹配**无扩展名**路径 | 必须排除 `/assets/*.js|css`：否则资源被当 HTML 返回（MIME=text/html），浏览器按 Strict MIME 拒绝执行 module 脚本，页面空白 |
| 演示台账 | 场景一资源 132 总 / 88 已分配 / 44 待分配、在线率 92%；方案名与 §7.3/§7.4 逐字一致 | 见 `backend/src/core/Seed.cc` |

### 10.3 AI 代理约定（易错点）

Python 桥 `/chat`、`/health` 返回的是**业务对象本身**（`{text,provider,intent,...}`），
而本系统对外统一为 `{code,message,data}`。因此 **C++ 代理负责套信封**：

- `/api/v1/ai/chat`、`/scenarios/recommend`、`/ai/health` → 套 `{code:0,message:"ok",data:{…}}`
- `/api/v1/ai/tts` → 音频二进制**原样透传**（不套信封），Content-Type 保持 `audio/mpeg`
- 桥不可达 → `code=2001`；桥返回非 200 → `code=2002`（前端据此降级为文本提示）

### 10.4 降级矩阵（实测）

| 场景 | 行为 |
|---|---|
| 无 `OPENAI_API_KEY` | `/chat` 走规则兜底（`provider="rule"`），文案与 §7.6 逐字一致；`/health` 三项能力均 `false` |
| 无 ffmpeg | `/tts` 返回占位音频（WAV）并在响应头说明；有 ffmpeg 时返回 `audio/mpeg` |
| 无瓦片数据 | 地图回落深色纯底 + MapLibre 矢量图层（轨迹/目标/链路/区域），演示不受阻 |
| 无视频素材 | 视频入口自动隐藏，不显示空面板 |
| 无麦克风权限（HTTP 非 secure context） | 语音入口退化为「快捷提问」按钮 + 文本输入 |
