## 1. 分级与状态约定

### 1.1 优先级

| 级别 | 定义 | 处理要求 |
|---|---|---|
| P0 | 阻断核心链路、造成严重数据错误或系统不可用 | 立即处理，阻断发布 |
| P1 | 核心能力失效、数据被覆盖、明显资源泄漏或需求承诺不成立 | 当前迭代优先修复 |
| P2 | 局部功能错误、边界问题、可维护性或性能风险 | 纳入近期迭代 |
| P3 | 低风险体验、规范与工程质量优化 | 按资源排期 |

### 1.2 类型与状态

- `Bug`：当前实现与接口、注释、需求或预期行为不一致。
- `优化`：当前未必立即出错，但存在性能、可维护性、可测试性或演进风险。
- 本文状态统一为 `待处理`；“代码确认”表示可由当前实现直接推导，仍建议修复后补充浏览器集成回归。

## 4. Bug 明细

### MAP2D-BUG-001：多实例操作可能写入错误地图

- 影响范围：双地图、实例切换、绘图、主题、图层控制与交互状态。
- 代码证据：`src/core/instanceRegistry.ts:33-78` 仅切换 `mapInstance.current`；`src/render/LayerManager.ts:99-110,172-174` 仍以静态字段保存最后初始化的地图；`src/core/instance.ts:7-16` 的就绪状态也为全局单例。
- 风险：调用 `setActiveInstance(id)` 后，`MapDraw` 和 `LayerManager` 命令仍可能落到另一张地图；任一实例卸载时还会把共享 `layersReady` 置为 `false`。
- 修复建议：引入按 `instanceId` 建立的 `MapContext`，将地图、LayerManager、图元集合、交互状态、计时器和可见性状态统一按实例管理。
- 验收标准：两个实例可分别增删图元、切换主题和图层；卸载任一实例不影响另一实例；不存在跨实例 Source 写入。

### MAP2D-BUG-002：底图切换后业务图层数据丢失

- 影响范围：`MapData` 驱动的目标、集群、无人机、链路和轨迹，以及交互绘制预览层。
- 代码证据：`src/ui/MapView.tsx:300-313` 重建样式后只执行 `LayerManager.init()` 与 `MapDraw.render()`；`src/ui/MapView.tsx:327-343` 的 `LayerSync` 依赖未变化，不会重新执行；`src/ui/DrawLayer.tsx:68-90,96-135` 只初始化一次临时 Source/Layer。
- 风险：换底图后，业务数据没有重放；交互预览 Source 被 `setStyle()` 删除，后续绘制没有预览和顶点手柄。
- 修复建议：统一监听 `style.load`，在样式完全可用后依次重建内部图层、重放业务快照、重放绘制快照、恢复透明度和交互层。
- 验收标准：在存在业务数据和绘制中间态时连续切换底图，所有业务图层、图元、图层设置和预览层均保持。

### MAP2D-BUG-003：多个写入方共享 Source 并相互覆盖

- 影响范围：`area/link/group/target/uav/track` 等数据源。
- 代码证据：`LayerSync` 与 `MapDraw` 都调用同一组 `LayerManager.set*` 方法；`src/primitives/api.ts:417-453` 中目标聚合气泡与 `cluster` 图元共用 `src-group`。
- 风险：任何一方更新都会整组 `setData()` 覆盖另一方；`renderAll()` 的迭代顺序还会导致聚合气泡和集群图元互相清空。
- 修复建议：为业务数据、自由图元、聚合结果和回放结果建立独立 Source，或在唯一数据仓库中按命名空间合并后单点提交。
- 验收标准：业务目标与 `MapDraw target`、业务集群与聚合气泡可同时显示，任一集合更新不会清空其他集合。

### MAP2D-BUG-004：几何简化容差单位错误

- 影响范围：顶点数超过阈值的轨迹、航线和多边形。
- 代码证据：`src/core/degrade.ts:77-84` 把像素换算为米；`src/core/degrade.ts:104-140` 在经纬度坐标上计算欧氏距离；`src/core/degrade.ts:167-176` 直接把米值作为经纬度容差传入。
- 风险：正常地图层级下容差可能达到数十或数百，而经纬度差通常远小于 1，长几何可能被错误压缩为首尾两个点。
- 修复建议：先将坐标投影到屏幕像素或米制平面再简化，完成后映射回经纬度；同时补充高纬度和跨日期变更线用例。
- 验收标准：相同几何在不同纬度和缩放级别下的视觉误差不超过配置像素容差，不出现异常塌缩。

### MAP2D-BUG-005：卸载与重新挂载清理不完整

- 影响范围：SPA 路由切换、热重载、地图销毁重建、长期运行资源占用。
- 代码证据：`src/ui/MapView.tsx:263-270` 未停止图元事件、脉冲和 FPS；`src/core/primitiveEvents.ts:103-137` 使用模块级 `bound`，且解绑函数没有移除匿名监听器；`src/primitives/api.ts:496-512` 的 `zoomHooked` 不会重置；`src/render/LayerManager.ts:479-516` 与 `src/core/diagnostics.ts:120-149` 均存在持续的 rAF 循环。
- 风险：重挂载后新地图可能不再响应图元点击、悬停和缩放重绘；卸载后动画循环仍占用 CPU，静态地图引用也可能滞留。
- 修复建议：保存所有事件函数引用并在 cleanup 中逐一 `off`；停止 rAF/interval；释放静态地图引用；重置缩放 Hook 和就绪状态。
- 验收标准：连续挂载/卸载 20 次后监听器与 rAF 数量不增长，新实例的点击、悬停和缩放重绘始终有效。

### MAP2D-BUG-006：缩放与比例尺控件关闭后无法重新开启

- 影响范围：`zoom`、`scale` 原生控件动态开关。
- 代码证据：`src/core/controls.ts:14-45` 用 WeakMap 中是否已有控件对象判断“已挂载”；`src/core/controls.ts:61-68` 移除控件后没有清除或更新该状态。
- 风险：执行“开启 → 关闭 → 再开启”时，第二次开启因 `has=true` 跳过 `addControl()`。
- 修复建议：分离“控件实例缓存”和“当前挂载状态”，移除成功后将挂载状态设为 `false`。
- 验收标准：缩放和比例尺控件分别循环开关 10 次均正常显示，DOM 中无重复控件。

### MAP2D-BUG-007：回放覆盖现有业务图元，且 label 轨迹不渲染

- 影响范围：回放前已有的无人机、目标、航线和标签图元。
- 代码证据：`src/core/replay.ts:228-263` 每帧整组调用 `MapDraw.set('drone'/'target'/'route')`；类型在 `src/core/replay.ts:29-39` 允许 `label`，但渲染阶段没有 `MapDraw.set('label')`；`clearReplay()` 在 `315-321` 直接清空三类图元。
- 风险：开始回放即覆盖实时业务数据，结束回放也无法恢复；`kind: 'label'` 的合法输入始终不显示。
- 修复建议：将回放内容放入独立命名空间或 Source；加载回放前保存并在清理时恢复现场；补齐 label 映射。
- 验收标准：回放与实时图元可共存；停止或清空回放后恢复原数据；三种声明的回放类型均正确显示。

### MAP2D-BUG-008：瓦片资源淘汰直接操作 MapLibre 私有缓存

- 影响范围：瓦片缓存一致性、显存释放、MapLibre 版本升级和诊断指标。
- 代码证据：`src/core/resources.ts:75-88,116-134` 访问 `style.sourceCaches.*._tiles` 并直接 `delete`；`resourceUsage()` 固定返回 `errors: 0`，`maxErrors` 配置没有连接到诊断数组。
- 风险：直接删除私有表项可能绕过瓦片卸载和 GPU 资源释放流程，导致内部索引失配、可见瓦片消失或升级后崩溃；资源指标与配置不真实。
- 修复建议：优先使用 MapLibre 公开缓存配置；确需适配私有 API 时封装版本守卫并调用完整卸载流程；把诊断容量收敛到同一配置源。
- 验收标准：缓存受控且不直接删除私有字段；压力缩放无空白瓦片、控制台异常和单调内存增长；错误数统计与上限一致。

### MAP2D-BUG-009：全局瓦片网络 Hook 无法真正卸载

- 影响范围：整个页面的 `window.fetch`、`XMLHttpRequest` 以及重复挂载场景。
- 代码证据：`src/core/tileNet.ts:70-110` 覆盖全局 fetch 与 XHR 原型；`src/core/tileNet.ts:113-116` 的卸载函数仅设置 `installed=false`，未恢复原函数。
- 风险：卸载后 Hook 仍影响宿主全部请求；再次安装会在旧包装上继续包装，造成重复统计、额外监听和难以排查的全局副作用。
- 修复建议：在模块级保存原始函数，引用计数管理安装者，最后一个实例卸载时按身份校验恢复原函数。
- 验收标准：安装和卸载前后函数引用可恢复；重复安装不会重复计数；非瓦片请求行为完全不受影响。

### MAP2D-BUG-010：空数据与阶段变化后存在陈旧覆盖物

- 影响范围：目标轨迹、无人机尾迹和扫描热点。
- 代码证据：`src/render/LayerManager.ts:685-694` 在空轨迹时直接返回，未清空 Source；`640-670` 只追加历史且不删除已离场无人机；`672-682` 只在 T3 写扫描热点，而 T4-T6 仍允许扫描层可见。
- 风险：业务传入空轨迹后旧轨迹残留；无人机离场后尾迹长期保留；阶段或场景切换后显示上一阶段热点。
- 修复建议：所有 setter 对空集合执行显式清空；按当前无人机 ID 集合裁剪历史；在阶段/场景变化时重建或清空扫描数据。
- 验收标准：非空到空、对象离场、T3 到其他阶段和场景切换均不残留旧要素。

### MAP2D-BUG-011：公开图元属性与渲染结果不一致

- 影响范围：区域、轨迹、脉冲、形状图元。
- 代码证据：`src/primitives/api.ts:409-449` 未把 `AreaItem.dashed` 和 `PulseItem.radiusKm` 传入有效渲染属性；`src/render/LayerManager.ts:192-200,272-276` 对区域和轨迹使用固定线型/颜色；形状 `label` 被写入要素但没有对应文字图层；`src/primitives/api.ts:311-333` 声明 0 度为正北，实际长轴在 0 度时沿东西方向。
- 风险：宿主传入合法字段但界面无变化，椭圆方向比接口语义偏转 90 度。
- 修复建议：为区域和轨迹使用实线/虚线分层及数据驱动颜色；明确脉冲半径是公里还是像素并落实；增加形状标签层；统一椭圆方位角公式。
- 验收标准：逐项建立视觉快照用例，所有公开样式字段均产生可观察且与文档一致的效果。

### MAP2D-BUG-012：图层整体透明度计算与恢复不正确

- 影响范围：同时含填充与描边透明度的图层，以及底图样式重建场景。
- 代码证据：`src/render/LayerManager.ts:872-903` 每个图层只缓存一个基准透明度，却把该值应用到该图层所有 opacity 属性；`MapView` 样式重建流程未重新调用已保存的分组透明度。
- 风险：例如扫描层原始填充透明度 0.10、描边透明度 0.55，设置整体透明度后两者会被错误统一；切换底图后用户设置丢失。
- 修复建议：按 `layerId + paintProperty` 保存原值，并在 `LayerManager.init()` 完成后集中重放全部透明度设置。
- 验收标准：不同 paint 属性保持原始比例；连续切换底图后分组透明度数值和视觉效果不变。

### MAP2D-BUG-013：移动图层组到目标之后时组内顺序可能反转

- 影响范围：`mapCommands.moveLayerGroup(group, target, 'after')`。
- 代码证据：`src/render/LayerManager.ts:805-827` 逐个计算锚点下一层并移动；当下一层是同组成员时，后移动的图层会插到先移动图层之前。
- 风险：发光层、主线、标签等组内叠放顺序被反转，产生遮挡或视觉样式异常。
- 修复建议：先从完整层序中计算最终目标序列，再按稳定顺序一次性移动；`after` 分支可逆序移动或使用组外固定锚点。
- 验收标准：所有分组从目标前后两个方向移动后，组内相对顺序与移动前完全一致。

### MAP2D-BUG-014：注册底图的初始选择与缩放约束未应用

- 影响范围：挂载前注册底图、底图级 `minZoom/maxZoom` 配置和运行时切换。
- 代码证据：`src/core/basemaps.ts:122-136` 的 `toConfig()` 未把定义中的层级范围写回配置；`src/ui/MapView.tsx:177-189` 初次建图直接使用 props 快照；`293-300` 又跳过第一次底图 effect；`initialBasemapConfig()` 虽导出但未在 MapView 初始化使用。
- 风险：注册表显示的当前底图与初始画面不一致；切换底图后地图相机约束仍沿用旧配置。
- 修复建议：初始化时明确合并 `initialBasemapConfig()`；切换时同步调用 `setMinZoom()`、`setMaxZoom()`，并将相关字段纳入变更键。
- 验收标准：挂载前注册的当前底图首帧即生效；每套底图切换后层级限制与定义一致。

### MAP2D-BUG-015：绘制 API 的输入校验、快照隔离和批处理异常语义不完整

- 影响范围：`track` 输入、`list()/export()` 返回值、`batch()` 异常路径。
- 代码证据：`src/core/validate.ts:53-55` 只校验轨迹点数量，不校验坐标结构与有限数；`src/primitives/api.ts:653-665` 只复制数组而复用内部对象；`588-597` 在回调抛错时不会执行 `flushDirty()`。
- 风险：非法轨迹坐标进入渲染层；调用方修改查询结果可绕过校验并直接污染内部状态；异常批次留下未提交的 dirty 集合。
- 修复建议：复用 route 的逐点校验；返回结构化克隆或只读快照；明确 batch 的事务语义，并在最外层 finally 中提交或回滚。
- 验收标准：NaN、Infinity 和错误坐标结构均被拒绝；修改查询结果不影响内部集合；异常批次后状态与渲染保持一致。

### MAP2D-BUG-016：双击完成绘制可能生成重复末端顶点

- 影响范围：折线、面和量算的双击完成流程。
- 代码证据：`src/ui/DrawLayer.tsx:232-240` 每次 click 都追加坐标；`311-315` 在 dblclick 时才完成绘制。浏览器双击事件通常在两个 click 之后触发。
- 风险：末端坐标被追加两次，形成零长度线段、重复面顶点，并影响长度、面积和后续编辑。
- 修复建议：双击完成时去除相邻重复点，或延迟单击提交并识别双击；同时设置合理的像素/地理距离去重阈值。
- 验收标准：连续双击完成的线面不存在相邻重复坐标，量算结果与相同顶点的 Enter 完成方式一致。

## 5. 优化项明细

### MAP2D-OPT-001：降低回放逐帧计算和提交成本

- 优先级 / 状态：P2 / 待处理。
- 代码证据：`src/core/replay.ts:228-263` 每帧按状态再次 `find()` 轨迹、对每条轨迹全量 `filter()` 历史点，并连续执行三次 `MapDraw.set()`；`loadReplay()` 使用展开运算计算全局最小/最大时间。
- 优化建议：加载阶段建立 `trackById` 与时间索引；用二分位置截取已通过点；通过 `MapDraw.batch()` 或单次 Source 提交合并渲染；用循环计算时间范围，避免超大数组展开风险。
- 验收标准：在约定最大轨迹数和采样点规模下，回放保持目标 FPS；每帧 Source 提交次数有明确上限；长数据加载无调用栈错误。

### MAP2D-OPT-002：测试应直接覆盖生产实现和核心集成链路

- 优先级 / 状态：P2 / 待处理。
- 代码证据：`scripts/unit-test.mjs:1-10` 明确复制算法并依赖人工同步；`package.json:8-14` 没有 `test` 脚本；当前 17 项用例未覆盖 MapView 生命周期、样式重建、Source 所有权和多实例。
- 优化建议：引入可直接导入 TypeScript 源码的测试运行器；保留纯函数单测，并增加 MapLibre mock 或浏览器集成测试；统一提供 `npm test` 和 CI 门禁。
- 验收标准：测试直接调用 `src` 实现；至少覆盖多实例隔离、换底图数据恢复、控件重复开关、回放清理、卸载重挂载和大几何简化。
